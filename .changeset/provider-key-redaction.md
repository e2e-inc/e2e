A model provider or coding agent that quotes your API key back, such as a proxy that puts the rejected key in its error, can no longer put it in the terminal, `report.json`, `summary.md`, or a trace page, and the run no longer sends it to the model in the screen, a tool result, the model's own prose, or a `system` text a config or an executor writes. The run redacts the keys of 20 to 8,192 characters (a value no pattern can be built for is left alone) in `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `AI_GATEWAY_API_KEY`, `OPENROUTER_API_KEY`, and the other model provider variables as `<secret:NAME>`, the tokens of a subscription login it sends, and the login `codex()` finds in `CODEX_HOME/auth.json`. `e2e/agent` exports `registerProviderKey`, `registerProviderKeys`, `redactSecrets`, and `redactStepText` for an executor, or a config that passes a key in code. A config that loads a key and then fails quoting it prints its marker too, in `e2e run`, `e2e list`, `e2e doctor`, `e2e cache`, `e2e report`, `e2e init`, and `e2e mcp`, and `list()` and `explore()` from `e2e/runner` now reject as `openHost` does, redacted and without the original `cause`. A key given as a model id is redacted from `e2e doctor`, the run header, `ai-trace.json`, and the model a step records. A failed model call's error, as a test or a program catches it, has its text redacted and no `cause`. A text download is rewritten for a provider key too, whole keys only, since a config can give the app one, and a provider key is never added to a session's saved secrets. `e2e run`, `e2e mcp`, and `openHost` now warn when `NODE_DEBUG` names `child_process` or `net`, which make Node print environments and request headers, where only e2e's own output is redacted, for its secrets and these keys, and `acp()` no longer passes `NODE_DEBUG` to the agents it starts. `@e2e-dev/acp` now needs `e2e` 0.24.1 or newer.
