A model provider or coding agent that quotes your API key back, such as a proxy that puts the rejected key in its error, can no longer put it in the terminal, `report.json`, `summary.md`, or a trace page, and the run no longer sends it to the model in the screen, a tool result, or the model's own prose. The run redacts the keys of 20 to 8,192 characters in `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `AI_GATEWAY_API_KEY`, `OPENROUTER_API_KEY`, and the other model provider variables as `<secret:NAME>`, the tokens of a subscription login it sends, and the login `codex()` finds in `CODEX_HOME/auth.json`. `e2e/agent` exports `registerProviderKey`, `registerProviderKeys`, and `redactSecrets` for an executor, or a config that passes a key in code. A config that loads a key and then fails to load prints its marker too, in `e2e run`, `e2e list`, `e2e doctor`, and `e2e mcp`. A provider key never turns on download rewriting, so a download keeps a key you gave the app, and is never added to a session's saved secrets. `e2e run`, `e2e mcp`, and `openHost` now warn when `NODE_DEBUG` names `child_process` or `net`, which make Node print environments and request headers, where only e2e's own output is redacted, for its secrets and these keys, and `acp()` no longer passes `NODE_DEBUG` to the agents it starts. `@e2e-dev/acp` now needs `e2e` 0.24.1 or newer.
