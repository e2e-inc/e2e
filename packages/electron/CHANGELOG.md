# @e2e-dev/electron

## 0.0.1

### Patch Changes

- [#2237](https://github.com/e2e-inc/e2e/pull/2237) [`73ea77e`](https://github.com/e2e-inc/e2e/commit/73ea77e22a78fd55b7b0e7bbbff12c347c09be27) Thanks [@kdy1](https://github.com/kdy1)! - New package: `@e2e-dev/electron`, the Electron engine. `engine: electron()` launches an Electron app (the project's `electron` package running `app.appPath`, or a packaged app through `executablePath`) on an empty user-data directory per attempt, and reads its windows through Chromium's accessibility tree over the DevTools protocol: observation, the `screen` locators and actions, test ids, masked screenshots, the app's windows as tabs, and the `electron` fixture with `evaluate` in the main process, `windows`, `waitForWindow`, `window`, `waitForDownload`, `onDialog`, and `locator`. It records video (the shown window's screencast, encoded with an ffmpeg it downloads on the first recording when the machine has none), and supports `app.back()`, `toBeInViewport`, computed-style reads, and in-memory `setInputFiles`. It uses only the public engine contract and has no runtime dependency: it starts the app and speaks the DevTools protocol itself, the windows over a pipe that opens no port. A window that has loaded no page does not hold up the launch, and a packaged app built with the `EnableNodeCliInspectArguments` fuse off launches too, without `electron.evaluate`. The app is started with only the variables a process needs to start and draw, plus `electron({ env })`, never the run's whole environment. `electron.onDialog('accept' | 'dismiss' | handler)` answers the app's `alert` and `confirm` dialogs, as `browser.onDialog` does on the web; one no handler takes is dismissed and fails the test's next step. A window that shows a local file outside the app's directory is not observed, traced, or captured. `electron` is a required peer: the fixture's types come from it.

- [#2406](https://github.com/e2e-inc/e2e/pull/2406) [`36683ed`](https://github.com/e2e-inc/e2e/commit/36683edb31e75a9668244d4dc230bd11d72b2a82) Thanks [@okwasniewski](https://github.com/okwasniewski)! - The `electron` fixture covers what a real app's suite needs beside `screen`:
  
  - `electron.launch({ launchArguments, env, cwd })` launches the app with arguments, environment variables, and a working directory of one test (`electron({ cwd })` sets the directory for every test), and `electron.userDataDir` is there before the launch, so a test can put data in it first. [Per-test arguments](https://e2e.com/docs/electron#launch-with-per-test-arguments)
  - `electron.keyboard` and `electron.mouse` send input to the active window, wherever its focus is: `await electron.keyboard.press('Escape')`. [Keyboard and mouse](https://e2e.com/docs/electron#keyboard-and-mouse)
  - `electron.activeWindow()` returns the window `screen` reads, and a window has `evaluate(fn, arg)`, which runs in its page, and `reload()`. [Run code in a window](https://e2e.com/docs/electron#run-code-in-a-window)
  
  Fixes:
  
  - A button drawn as an icon font's glyph and text, such as `<button><i class="fa fa-search"></i> Scan</button>`, is named `Scan`, as on the web. The glyph was part of its name, so `getByRole('button', 'Scan')` found nothing.
  - `getByText` on text in a container such as a toolbar, inside elements the accessibility tree leaves out, taps the text. It tapped the middle of the container, which could miss the element that handles the click.
  - A step that starts while the active window closes, such as a sign-in popup that closes itself, reads the window active after it instead of failing with `APP_NOT_OPEN`.
  - `locator.focus()` succeeds when the element hands focus to a part of itself, as a grid row does to its editor. It failed with `ACTION_FAILED`.

- [#2237](https://github.com/e2e-inc/e2e/pull/2237) [`73ea77e`](https://github.com/e2e-inc/e2e/commit/73ea77e22a78fd55b7b0e7bbbff12c347c09be27) Thanks [@kdy1](https://github.com/kdy1)! - `electron.evaluate` types the `electron` module its function receives with the project's own `electron` package, a required peer, in place of `any`.

- [#2408](https://github.com/e2e-inc/e2e/pull/2408) [`727071e`](https://github.com/e2e-inc/e2e/commit/727071ea3e063208cf60033b6358134c68d80f6f) Thanks [@okwasniewski](https://github.com/okwasniewski)! - On Windows, `electron({ executablePath })` must name the app's `.exe`. A shortcut, a script, a folder, a path without `.exe`, or the launcher a Squirrel installer leaves beside the app now fails the config check and `e2e doctor`, with the file to name instead.

- [#2412](https://github.com/e2e-inc/e2e/pull/2412) [`5a2adf1`](https://github.com/e2e-inc/e2e/commit/5a2adf15f23715044959de5f37263f21c157eb0b) Thanks [@okwasniewski](https://github.com/okwasniewski)! - On Windows and Linux, screenshots and video of a window the app showed and then hid with `hide()` work. A screenshot used to wait out the whole timeout, and a recording wrote no video. The engine now starts every window with `backgroundThrottling` off.

- [#2367](https://github.com/e2e-inc/e2e/pull/2367) [`b70181b`](https://github.com/e2e-inc/e2e/commit/b70181b8a925733c9166b56a04b72d44878ffca0) Thanks [@okwasniewski](https://github.com/okwasniewski)! - **Breaking:** `getByText` on a device or a desktop app no longer matches a node by its accessible name when the node shows text of its own. It matches the text the node shows, and the name only of a node that shows none, such as an icon button. Replace `getByText(name)` with `getByLabel(name)`, or query the text the node shows. This affects a text an app names otherwise, an Android text or filled field with a content description (`<Text accessibilityLabel="Total price">$5</Text>` answers `getByText('$5')` and `getByLabel('Total price')`), and an empty Android field with a description, which `getByText` finds by its hint. A value named by the label beside it (a `5` named `Words`) no longer makes `getByText('Words')` ambiguous. `filter({ hasText })` still reads names, text, and values. `resolveExpression` from `@e2e-dev/core/engine` follows the same rule, and `shownText(node)` is exported beside it for an engine that matches text itself. On the desktop engine a row or a cell reads the text inside it as its text, without the text scrolled out of it while the row itself is on screen, and a web view's heading reads its title as its text and its level from the number it reports as its value. `@e2e-dev/mobile` and `@e2e-dev/desktop` now need `@e2e-dev/core` and `e2e` 0.26.0 or newer. The web and Electron engines are released with it and read text as before.
