`@e2e-dev/web` はブラウザエンジンです。WebDriver BiDi 経由で Chromium と Firefox を操作します。Web ターゲットには `web()` でエンジンを指定します。ブラウザ専用の操作には、このエンジンが提供する組み込みフィクスチャ `browser` を使います。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';

export default {
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
} satisfies E2EConfig;
```

`browser` に型を付けるには、このパッケージから `test` をインポートします。

```ts title="tests/orders.e2e.ts"
import { expect } from 'e2e';
import { test } from '@e2e-dev/web';

test('orders in dark mode', async ({ app, browser, screen }) => {
  await browser.emulateMedia({ colorScheme: 'dark' });
  await app.open('/orders');
  await expect(browser).toHaveURL('/orders');
  await expect(screen.getByRole('heading', { name: 'Orders' })).toBeVisible();
});
```

## リファレンス

### オプション

`web(options)` は、エンジンがアプリを操作する方法を設定します。アプリ自体の `url`、`environment`、`identity`、起動コマンドは、ターゲットの `app` に設定します。[テスト対象のアプリ](/reference/config#the-app-under-test)を参照してください。

```ts
web({ viewport: { width: 390, height: 844 }, locale: 'de-DE' });
```

| オプション | 型 | デフォルト |
| --- | --- | --- |
| [`browser`](#browser) | `BrowserName \| BrowserProvider` | `'chromium'` |
| [`viewport`](#viewport) | `ViewportSize \| null` | 1280 × 720 |
| [`screencast`](#screencast) | `WebScreencastOptions` | ビューポートのサイズ |
| [`connect`](#connect) | `WebConnectOptions` | ローカルで起動 |
| [`headers`](#headers) | `Record<string, string>` | - |
| [`basicAuth`](#basicauth) | `WebBasicAuth` | - |
| [`credentialOrigins`](#credentialorigins) | `string[]` | - |
| [`testIdAttribute`](#testidattribute) | `string` | `'data-testid'` |
| [`userAgent`](#useragent) | `string` | ブラウザ自身の値 |
| [`locale`](#locale) | `string` | ブラウザ自身の値 |
| [`timezoneId`](#timezoneid) | `string` | マシンの設定 |
| [`colorScheme`](#media-emulation) | `'light' \| 'dark' \| 'no-preference'` | ブラウザ自身の値 |
| [`reducedMotion`](#media-emulation) | `'reduce' \| 'no-preference'` | ブラウザ自身の値 |
| [`initScripts`](#init-scripts) | `WebInitScript[]` | - |

- `web()` ターゲットには `app.url` が必須です。デバイス用のキー（`bundleId`、`appPath`、`launchArguments`）は拒否します。`app.permissions` は、ブラウザが許可できる権限名に対する `'grant'` だけを受け付けます。[`permissions`](/reference/config#permissions) を参照してください。
- `app.url` を持つターゲットは `browser` ターゲットなので、`requires: ['browser']` で Web ターゲットを選択できます。
- JSDoc を含む完全な宣言は、型セクションの [`WebOptions`](#weboptions) にあります。

| エラー | 発生条件 |
| --- | --- |
| `INVALID_CONFIG` | `web()` が受け付けないオプション（`url` などアプリのキーも含む）、または `connect` や `basicAuth` 内に未知のキーがある場合。タイプミスと思われる場合は最も近い既知のキー（`viewprt` なら `viewport`）、それ以外はすべてのキーを示します。 |

#### `browser`

起動するブラウザ、またはホスト型ブラウザをリースするプロバイダーです。

```ts
web({ browser: 'firefox' }); // default: 'chromium'
```

- `'chromium'` または `'firefox'` を指定できます。使用するビルドは[ブラウザのインストール](#installing-browsers)にあります。
- `BrowserProvider` を渡すと、代わりにホスト型ブラウザをリースします。実行中のワーカースロットごとに 1 つ、`scope: 'attempt'` では試行ごとに 1 つです。エンジンは、それぞれを chromium として CDP 経由で操作します。
- `scope: 'attempt'` では、各試行はリースしたブラウザ自身のコンテキストで動きます。`app.clearState()` は `UNSUPPORTED_CAPABILITY` をスローし、保存済みセッションを使うテストは収集時に `COLLECTION_ERROR` で失敗します。
- [ホスト型ブラウザ](/browser#hosted-browsers)に `BrowserProvider` の契約と実装例があります。

| エラー | 発生条件 |
| --- | --- |
| `INVALID_CONFIG` | `'webkit'` を含め、ほかのブラウザ名を指定した場合。 |
| `INVALID_CONFIG` | `browser: provider` と `connect` を併用した場合。 |

#### `viewport`

各試行のページの初期ビューポートです。

```ts
web({ viewport: { width: 390, height: 844 } }); // default: { width: 1280, height: 720 }
```

`null` はサイズをエミュレートせず、ページがブラウザウィンドウ全体を使う指定です（[`WebOptions`](#weboptions)）。その場合も [`browser.setViewport`](#setviewport) で固定サイズにできます。

#### `screencast`

動画を記録する試行で、エンジン自身のスクリーンキャストをどう録画するかを設定します。

```ts
web({ screencast: { size: { width: 800, height: 450 }, quality: 60 } });
```

- `size` は整数のピクセル数で、各辺は 1 以上です。Firefox ではフレームがビューポートの縦横比を保つため、`size` の内側に収まる大きさになります。
- `quality` は整数で、未設定の場合は `90` です。Chromium だけに適用され、Firefox は無視します。
- どの試行を録画するかは、設定の [`video`](/reference/config#video) モードで決まります。

```ts
/** The engine's screencast of the page: the frame size and the JPEG quality of the frames it encodes. */
export interface WebScreencastOptions {
  /** Frame size in pixels; default the viewport's, or the window's under `viewport: null`. A smaller size makes a smaller file. */
  readonly size?: ViewportSize;
  /** JPEG quality of each captured frame, 0 through 100; 90 when unset. Chromium only: Firefox ignores it. */
  readonly quality?: number;
}
```

| エラー | 発生条件 |
| --- | --- |
| `INVALID_CONFIG` | 設定の読み込み時に、無効な `size` や `quality`、またはほかのキーがある場合。古い `web({ video })` という指定も拒否し、`screencast` を案内します。 |

#### `connect`

ローカルで起動せず、CDP 経由でリモートの Chromium に接続します。

```ts
web({ connect: { cdpEndpoint: async () => 'ws://127.0.0.1:9222' } });
```

- `cdpEndpoint(signal)` は、ワーカーが初めてブラウザを必要とした時点で解決されます。接続が切れた後に試行が始まるときにも、もう一度解決されます。
- 各試行は、リモートブラウザ上に新しいブラウザコンテキストを取得します。コンテキストを作成できないホストでは、試行が `UNSUPPORTED_CAPABILITY` で失敗します。
- `context: 'existing'` は、コンテキストとタブを作成せず、ブラウザがすでに表示しているページを操作します。Electron アプリなど、どちらも作成できないホスト向けです。`app.open()` はそのページを遷移させ、試行はそのページの Cookie とストレージを共有し、ターゲットは 1 つのワーカーで動きます。試行が終わると、そのページが開いたタブを閉じ、試行がブラウザに設定した内容を元に戻します。
- 接続が切れると試行は失敗し、次の試行が `cdpEndpoint` を通して再び接続します。

`cdpEndpoint` は、CDP ハンドシェイクを認証するために `CdpTarget` として `{ endpoint, headers }` を返せます。このヘッダーは、アプリに送る `web({ headers })` とは別です。

```ts
export interface WebConnectOptions {
  readonly cdpEndpoint: (signal: AbortSignal) => string | CdpTarget | Promise<string | CdpTarget>;
  readonly context?: 'new' | 'existing';
}
```

| エラー | 発生条件 |
| --- | --- |
| `INVALID_CONFIG` | 設定の読み込み時に、`connect` に `cdpEndpoint` がない、または文字列で指定されている場合。`connect` と `browser` プロバイダーの併用、chromium 以外の `browser`、`'new'` と `'existing'` 以外の `context` も該当します。 |

ファイルをまたいで 1 回のサインインを再利用するには、[セットアップテストで 1 回サインイン](/authentication#reuse-authenticated-sessions)してください。認証状態は共有ブラウザではなく、保存済みセッションで引き継ぎます。

#### `headers`

アプリのオリジン（`app.url` のスキーム、ホスト、ポート）から始まるすべてのリクエストに加えるヘッダーです。別ポート、サブドメイン、ほかのホストから始まるリクエストには付きません。リダイレクトでは、転送先のオリジンにかかわらず、最初のリクエストのヘッダーを維持します。

```ts
web({ headers: { 'x-preview-token': process.env.PREVIEW_TOKEN ?? '' } });
```

- 許可されたオリジンへ向かう、[続行した](#route)リクエストにも付きます。
- `headers` と `basicAuth` は、[保護されたプレビュー](/web#protected-previews)にアクセスするための設定です。
- [リクエストの認証情報](/reference/security#request-credentials)を参照してください。

| エラー | 発生条件 |
| --- | --- |
| `INVALID_CONFIG` | `user-agent` と [`userAgent`](#useragent)、または `accept-language` と [`locale`](#locale) を併用した場合。 |

<Note>
`headers` は Service Worker をブロックします。
</Note>

#### `basicAuth`

HTTP Basic 認証の設定です。ブラウザは、アプリのオリジンからの `401` チャレンジにこの認証情報で応答します。ほかのオリジンには、[`credentialOrigins`](#credentialorigins) に列挙していない限り応答しません。

```ts
import { secrets } from 'e2e';

web({ basicAuth: { username: 'staging', password: secrets.get('staging-password') } });
```

`secrets.get(name)` のパスワードは各試行の開始時に解決し、設定済みのほかのシークレットと同じように伏せ字にします。それを Base64 化した `Authorization` ヘッダーの認証情報も同様です。

```ts
/** HTTP basic authentication the browser answers a `401` challenge from the app's origin with. */
export interface WebBasicAuth {
  /** The user name; `:` is not allowed in one (RFC 7617). */
  readonly username: string;
  /** The password, or `secrets.get(name)` for one in `config.secrets`. */
  readonly password: string | Secret;
}
```

| エラー | 発生条件 |
| --- | --- |
| `INVALID_CONFIG` | ユーザー名に `:` があるか、未知のキーがある場合。 |

<Warning>
シークレットの保護対象はテキストだけです。ページがパスワードを画面に表示した場合、スクリーンショットやモデルに送る画像ではマスクされません（[セキュリティルール](/reference/security#secrets-in-engine-options)）。
</Warning>

#### `credentialOrigins`

アプリ自身のオリジン以外に、[`headers`](#headers) と [`basicAuth`](#basicauth) を受け取るオリジンを追加します。同じアクセス制限の背後にある別ホストの API などに使います。

```ts
web({
  headers: { 'x-preview-token': process.env.PREVIEW_TOKEN ?? '' },
  credentialOrigins: ['https://api.staging.example.com'],
});
```

各オリジンを正確に列挙してください。ホスト内の `*` やポート `0` は、どのリクエストにも一致しません。

| エラー | 発生条件 |
| --- | --- |
| `INVALID_CONFIG` | `headers` も `basicAuth` もない、エントリーがパス・クエリ・フラグメントのない `http:` または `https:` のオリジンではない、ホストに `*` がある、ポートが `0` の場合。 |

#### `testIdAttribute`

要素のテスト ID を持つ属性です。`testId` クエリ（`screen.getByTestId`）が解決し、`SemanticNode.testId` が報告する値になります。

```ts
web({ testIdAttribute: 'data-test' }); // default: 'data-testid'
```

#### `userAgent`

各試行のコンテキストが送信し、`navigator.userAgent` が返す `User-Agent` です。ユーザーエージェント文字列の識別子でテストモードに切り替えるアプリなどに使います。

```ts
web({ userAgent: 'Mozilla/5.0 e2e' }); // default: the browser's own
```

#### `locale`

各試行のコンテキストが使うロケールを、BCP 47 タグで指定します。`navigator.language`、`Intl` の書式、`Accept-Language` ヘッダーに反映されます。

```ts
web({ locale: 'de-DE' }); // default: the browser's own
```

#### `timezoneId`

各試行のコンテキストが使う IANA タイムゾーンです。`Date` と `Intl` がローカル時刻を解決する基準になります。

```ts
web({ timezoneId: 'Europe/Berlin' }); // default: the machine's
```

#### メディアのエミュレーション

`web({ colorScheme, reducedMotion })` は、各試行のすべてのページが報告するメディア特性を設定します。`browser.emulateMedia(media)` は、1 回の試行について変更します。

```ts
web({ colorScheme: 'dark', reducedMotion: 'reduce' }); // default: the browser's own
await browser.emulateMedia({ colorScheme: 'light' });
```

- ページの `@media` ルールと `matchMedia` は、最初の描画からこの値を読みます。
- `emulateMedia` は、開いているすべてのタブと今後開くタブに、試行の残りの期間適用します。`app.restart()` と `app.clearState()` をまたいでも維持します。
- 最初のページ遷移前にも使えるため、次の `app.open` はその値で読み込みます。
- 省略した特性は現在の値を維持します。
- アプリ自身が開くタブには、タブが現れた時点でテストによる変更を適用します。そのため、読み込み時のスクリプトは設定ファイルの値を読むことがあります。

```ts
/** User preferences a page reads through `@media` rules and `matchMedia`. */
export interface WebMedia {
  /** `prefers-color-scheme`. */
  readonly colorScheme?: 'light' | 'dark' | 'no-preference';
  /** `prefers-reduced-motion`. */
  readonly reducedMotion?: 'reduce' | 'no-preference';
}
```

| エラー | 発生条件 |
| --- | --- |
| `INVALID_CONFIG` | `web()` で `WebMedia` にない特性や値を指定した場合。 |
| `INVALID_ARGUMENT` | `emulateMedia` で `WebMedia` にない特性や値を指定した場合。 |
| `UNSUPPORTED_CAPABILITY` | Firefox で、`emulateMedia` に `reducedMotion` を指定した場合。代わりに `web({ reducedMotion })` を設定してください。 |

#### 初期化スクリプト

初期化スクリプトは、すべてのタブとフレームの各ドキュメントで、ページ自身のスクリプトより先に実行します。`web({ initScripts })` はすべてのテストに適用し、`browser.addInitScript` はそのテストの残りの期間に追加します。

```ts
await browser.addInitScript((value) => { Math.random = () => value; }, 0.5);
await app.open('/raffle');
```

- 関数はテストの変数をクロージャーで参照できません。代わりに JSON の `arg` を渡してください。
- ページが開いた後に追加したスクリプトは、次の遷移または再読み込みから実行します。
- `browser.addInitScript` は同じ 3 形式に加え、関数と JSON の `arg` を受け付けます。オーバーロードは [`Browser`](#browser-interface) にあります。

```ts
/** JavaScript source, a file relative to the project root, or a function. */
export type WebInitScript = string | { readonly path: string } | (() => unknown);
```

#### 制限

| 制限 | 理由 |
| --- | --- |
| WebKit には対応しません | WebKit には WebDriver BiDi のエンドポイントがありません。 |
| `connect` とブラウザプロバイダーは Chromium 専用です | どちらも CDP 経由で接続します。 |
| `connect.reconnectEndpoint` は削除されました | 切れた接続を、試行の途中で復旧することはありません。次の試行が再び接続します。 |
| `connect.context: 'existing'` では、`app.clearState()` が `UNSUPPORTED_CAPABILITY` をスローし、保存済みセッションは拒否され、ターゲットは 1 つのワーカーで動きます | テストは、ブラウザが表示している 1 つのページを、ブラウザ自身のコンテキストで操作します。 |
| ブラウザが表示しているタブが 2 つある場合、または複数のタブがあってどれも表示されていない場合、`attachBrowser` と `connect.context: 'existing'` は `UNSUPPORTED_CAPABILITY` をスローします | ブラウザが報告する情報からは、どのタブを操作すべきか分かりません。Electron は `show: false` のウィンドウも表示中として報告します。 |
| `attachBrowser` と `connect.context: 'existing'` では、開いたまま残したページに、初期化スクリプトなどのスクリプトがそこで行った変更が、ページが遷移するまで残ります | ページはホストのもので、再読み込みは行われません。 |
| `scope: 'attempt'` のプロバイダーでは、`app.clearState()` が `UNSUPPORTED_CAPABILITY` をスローし、保存済みセッションは `COLLECTION_ERROR` になります | 試行は新しいブラウザ自身のコンテキストで動きます。どちらも、そのコンテキストを置き換えてしまう操作です。 |
| セレクターは CSS と XPath で、単独でも `>>` で連結しても使えますが、`text=` や `nth=` のセレクターエンジンはありません | セレクターはページ自身が実行します。 |
| Chromium では、`noopener` のタブ（`target="_blank"` のリンク）を開くアクションが、新しいタブのサーバーが応答するまで待ちます | chromium-bidi は、新しいタブの作成が終わるまですべてのメッセージを保留し、タブの作成は最初のレスポンスを待ちます（[crbug 372842894](https://crbug.com/372842894)）。 |
| Firefox では、`browser.emulateMedia({ reducedMotion })` が `UNSUPPORTED_CAPABILITY` をスローします | Firefox が実行時に変更するのは `prefers-color-scheme` だけです。代わりに `web({ reducedMotion })` を設定してください。 |
| Firefox では、HTML5 のドラッグを開始するドラッグ（`draggable` 要素）が `UNSUPPORTED_CAPABILITY` をスローします | [Firefox bug 1515879](https://bugzilla.mozilla.org/show_bug.cgi?id=1515879): Firefox はどこにもドロップしません。ポインターによるドラッグは動作します。 |
| Firefox では、`route.continue({ url })` が `UNSUPPORTED_CAPABILITY` をスローします | [Firefox bug 2014825](https://bugzilla.mozilla.org/show_bug.cgi?id=2014825): ページは、書き換えた URL の読み込みに失敗します。`route.fulfill` を使ってください。 |
| Firefox では、`route.fulfill` がリダイレクトで応答したリクエストに対する `waitForResponse` は、解決しません | Firefox は、そのレスポンスを報告しません。リダイレクト先の URL を待ってください。 |
| Firefox では、`waitForResponse` は、ヘッダーが届いた時点ではなく、レスポンスの本文が始まった時点で解決します | Firefox がレスポンスを報告するのは、その時点になってからです。 |
| Firefox では、`MediaPlayPause` など、WebDriver が値を定義していないキーが `UNSUPPORTED_CAPABILITY` をスローします | Chromium は、これらのキーを CDP 経由で押します。 |
| Firefox では、ウィンドウを広げても収まらないビューポートが `UNSUPPORTED_CAPABILITY` をスローします | Firefox は、ウィンドウの内側でしかポインター入力を受け付けません。ヘッドレスのウィンドウは縦横それぞれ 16384 ピクセルまで、headed のウィンドウはディスプレイの大きさまで広がります。 |
| Chromium では、`/favicon.ico` へのリクエストが、対応するルートを通らずにネットワークへ送られます | chromium-bidi は、このリクエストのイベントを報告しません。 |
| Chromium では、フォーム内にディスク上のファイルを含む本文、またはストリーミングされる本文を持つリクエストのルートは、`route.request.postData` を受け取らず、`route.fetch()` は `ACTION_FAILED` をスローします | Chromium は、その部分のバイト列を報告しません。`route.continue()` は、その場合も送信します。 |
| Firefox では、本文が 20 MB を超える、またはバイナリデータで 15 MB を超えるリクエストのルートは、`route.request.postData` を受け取らず、`route.fetch()` は `ACTION_FAILED` をスローします | Firefox がリクエスト本文を保持するのは、保存時の形式で 20 MB までで、バイナリデータは base64 として保存します。`route.continue()` は、その場合も本文全体を送信します。 |
| Firefox では、[アプリのログ](/debugging#traces)が、ログに出力されたイベントを `object` と表示し、クラスのインスタンスをクラス名なしで表示します | Firefox は、イベントについては何も報告せず、インスタンスについてはフィールドだけを報告します。 |
| Firefox では、動画がページの最後の再描画の 1 つ前で終わることがあり、開始から約 2 フレーム以内に停止した動画にはフレームが含まれません | Firefox は独自のクロックでページを録画し、取得した内容を何も報告しません。 |
| Firefox では、初期化スクリプトが見るのは、同一オリジンのフレームの最初の空のドキュメント（`about:blank`）であり、フレームがその後に読み込むページではありません | Firefox は、そのドキュメントの `window` をページでも使い続け、スクリプトを再実行しません。スクリプトが `window` に設定した内容は残ります。 |
| Firefox では、`browser.evaluate` が複数回実行されることがあります。`browser.newTab()` で開いたタブが最初のページを読み込むときにまだ実行中のもの、または別サイトへのページ遷移がコミットされる間に開始したものが該当します | Firefox は、コマンドの送信先だった空のドキュメント（新しいタブの最初のドキュメント、新しいサイトのプロセスが最初に持つドキュメント）がページに置き換わると、コマンドを再送します。`waitForURL` などで、先にページを待ってください。 |
| ブラウザプロバイダーでは、`setInputFiles` はファイルのバイト列を合計 50 MB までページに送り、ディレクトリには `UNSUPPORTED_CAPABILITY` をスローします。ダウンロードは、プロバイダーが提供しない場合に同じエラーをスローします | ブラウザのファイルシステムは、別のマシンのものです。 |
| 保存済みセッションは、JSON でも `Date` でもない IndexedDB の値に対して `UNSUPPORTED_CAPABILITY` をスローします | `Blob` やクラスインスタンスは復元できません。 |

### browser フィクスチャ

`browser` はブラウザ全体を表し、1 つのアクティブなタブを表示します。

- ページを読む操作やアクションは、アクティブなタブに対して行います。`goto`、`reload`、`back`、`forward`、`url`、`title`、`waitForURL`、`locator`、`frameLocator`、`evaluate`、`waitForResponse`、`waitForDownload`、`keyboard`、`mouse`、`expect(browser)` のマッチャー、すべての `screen` クエリが対象です。
- ブラウザ全体に属する操作は、すべてのタブに適用します。`cookies`、`setCookies`、`clearCookies`、`route`、`unroute`、`unrouteAll`、`onDialog`、`addInitScript` が対象です。
- `setViewport` は、アクティブなタブと、それ以降にアクティブになるタブのサイズを設定します。
- [`emulateMedia`](#media-emulation) は、すべての既存タブと今後のタブのメディア特性を変更します。
- `target="_blank"` のリンクや `window.open` からアプリが開くタブは、バックグラウンドで開きます。`waitForPopup` または `activate` で別のタブをアクティブにするまで、現在のタブは変わりません。[タブ](#tabs)を参照してください。
- `locator` と `frameLocator` を除くすべての `browser` 呼び出しは、`browser.<method>` ステップとして記録します。この 2 つはページに触れずにロケーターを作り、それを使うアクションやアサーションがステップになります。
- 相対 URL はターゲットの `app.url` を基準に解決します。なければ `APP_URL_REQUIRED` です。
- ほかのプラットフォームでも動くスイートでは、`requires: ['browser']` を宣言してください。
- `expect(browser)` は、エンジンが付ける `BrowserExpectation` を返します。`toHaveURL`、`toHaveTitle`、`toHaveClass` を使えます。[browser のマッチャー](/reference/expect#browser-matchers)を参照してください。

各メンバーの時間上限は[設定](/reference/config)で決まります。

- `goto`、`reload`、`back`、`forward`: `app.open()` と同じ [`timeout`](/reference/config#timeout)。

#### `goto`

アクティブなタブを指定の URL に遷移させます。

```ts
await browser.goto('/dashboard', { waitUntil: 'networkidle' }); // default: 'load'
```

`waitUntil` は `'load'`、`'domcontentloaded'`、`'networkidle'` のいずれかです。

| エラー | 発生条件 |
| --- | --- |
| `POLICY_DENIED` | URL のスキームが `http:` または `https:` 以外の場合。`about:blank` は許可されます。 |
| `APP_URL_REQUIRED` | `app.url` のないターゲットで相対 URL を指定した場合。 |
| `INVALID_ARGUMENT` | `waitUntil` が 3 つのいずれでもない場合。 |
| `ACTION_FAILED` | ページが時間内に読み込まれなかったか、[ルート](#route)がリクエストを中断した場合。 |
| `ENGINE_FAILURE` | ブラウザが URL を読み込めなかった場合。接続の拒否、不明なホスト、内容のないレスポンスが該当します。 |

#### `reload`、`back`、`forward`

`reload` は現在のドキュメントを再読み込みします。`back` と `forward` はブラウザ履歴を 1 つ戻る、または進む操作で、移動先の履歴がなければ何もしません。いずれもドキュメントの読み込みを待ちます。Chromium と Firefox はどちらも戻る・進むキャッシュを無効にして起動するため、`back` と `forward` はページをもう一度読み込みます。`connect` またはブラウザプロバイダーを通して接続したブラウザは、読み込み済みのドキュメントをこのキャッシュから復元することがあります。アプリの内容を待つには、ロケーターとアサーションを使ってください。

```ts
await browser.reload();
await browser.back({ timeout: 10_000 });
```

| エラー | 発生条件 |
| --- | --- |
| `ACTION_FAILED` | ページが時間内に読み込まれなかった場合。 |
| `ENGINE_FAILURE` | ブラウザがページを読み込めなかった場合。 |

#### `url`、`title`

アクティブなタブの現在の URL とタイトルを返します。

```ts
const url = await browser.url();
const title = await browser.title();
```

#### `waitForURL`

現在の URL が一致するまで待ちます。開始から 0、20、50 ms、その後は 100 ms ごとに URL を読みます。`expect(browser).toHaveURL` と同じポーリングです。

```ts
await browser.waitForURL(/\/orders\/\d+$/, { timeout: 15_000 });
```

- 相対文字列はベース URL を基準に解決し、正規化後に完全一致で比較します。
- `RegExp` は URL 全体に適用します。

| エラー | 発生条件 |
| --- | --- |
| `INVALID_ARGUMENT` | パターンが文字列や `RegExp` ではない場合（述語関数など）、または Playwright の `waitUntil` など、`timeout` 以外のオプションがある場合。 |
| `ASSERTION_FAILED` | タイムアウトまでに URL が一致しなかった場合。 |

#### `locator`

CSS または XPath のセレクターから、Web 専用のロケーターを作ります。

```ts
const conditions = browser.locator('[data-testid="row"]').nth(2).getByTestId('conditions');
```

- セレクターはデフォルトで CSS です。`xpath=`、先頭の `/`、先頭の `..` のいずれかで XPath になり、`css=` で CSS を強制します。
- CSS は、開いたシャドウルートの中にも届きます。
- `>>` は CSS と XPath の部分を連結し、各部分は直前の部分が一致した要素の内側で照合します。`text=` や `nth=` のセレクターエンジンはありません。代わりに、例のように `nth` と screen クエリを連結してください。
- 部分の中の `:scope` は、直前の部分が一致した要素です。Playwright とは異なり、その兄弟要素には届かないため、`:scope + p` は何にも一致しません。
- `:scope` は `:is()` と `:not()` の外に書いてください。これらの内側に書くと、部分の末尾を除き、その複合セレクターは `:scope` の要素だけに一致します。`p:not(:scope) > button` は何にも一致しません。
- 別の要素を内包する要素には、`filter({ has })` を使います。

| エラー | 発生条件 |
| --- | --- |
| `INVALID_LOCATOR` | 空のセレクター、または有効な CSS でも XPath でもないセレクター。 |

<Note>
すべての `screen` クエリは、スコープとその下にページが作った閉じたシャドウルートを検索します。ロール、名前、テキスト、ラベル、属性の照合には Playwright のルールを使い、各ノードは 1 回だけ取得します。観測ツリーに載る閉じたルート内のコントロールも解決でき、アクションと読み取りを行えます。`locator`、`frameLocator`、`filter({ hasText })` は、閉じたルートには入りません。詳細は[ブラウザガイド](/browser#shadow-dom)を参照してください。
</Note>

#### `frameLocator`

1 つの iframe 内に、screen クエリのスコープを作ります。

```ts
const payment = browser.frameLocator('#payment-frame');
await payment.getByLabel('Card number').fill('4242424242424242');
```

フレーム内からクエリ結果を返す `Screen` である `FrameScreen` を返します。フレームの `locator` は、コントロールにアクセシブルな名前、ラベル、プレースホルダー、テスト ID がない場合にだけ使ってください。該当する状況は[ブラウザガイド](/browser#reach-into-an-iframe)で説明しています。

```ts
export interface FrameScreen extends Screen {
  /** Creates a web-only CSS or XPath locator inside this frame. */
  locator(selector: string): Locator;
  /** Creates a screen query scope inside an iframe nested in this frame. */
  frameLocator(selector: string): FrameScreen;
}
```

ページとフレーム内で、エラーは同じです。

| エラー | 発生条件 |
| --- | --- |
| `INVALID_LOCATOR` | ここ、またはフレームの `locator` に空のセレクターを渡した場合。 |
| `LOCATOR_NOT_FOUND` | 一致するフレームがない場合。 |
| `LOCATOR_AMBIGUOUS` | 複数のフレームが一致した場合。 |

#### `evaluate`

信頼できるテストコードをページ内で評価し、結果を返します。

```ts
const count = await browser.evaluate(() => document.querySelectorAll('li').length);
const flag = await browser.evaluate(
  (name: string) => window.localStorage.getItem(name),
  'featureFlags',
);
const title = await browser.evaluate<string>('document.title');
```

- 関数はページ内で動き、テストの変数にはアクセスできません。e2e は関数のソースをシリアライズしてページに埋め込むため、本体の外にある値をクロージャーで参照しないでください。本体内で宣言したヘルパーは使えます。外部の値は `arg` で渡します。
- 文字列は文の列ではなく、1 つの式として評価します。結果が関数なら `arg` を渡して呼び、それ以外ならその値を結果にします。
- どちらも Promise を返した場合は await します。

| エラー | 発生条件 |
| --- | --- |
| `INVALID_ARGUMENT` | `arg` または戻り値が [`JsonValue`](#jsonvalue) ではない場合。`DOMRect` や要素などのクラスインスタンスは該当しません。`rect.toJSON()` または必要なフィールドを返してください。 |
| `EVALUATE_FAILED` | 評価したコードが例外をスローした場合。エラーにメッセージを含めます。 |
| `ACTION_FAILED` | 評価が時間内に完了しなかった場合。 |
| `ENGINE_FAILURE` | ページが閉じたか、コンテキストが失われた場合。 |

#### `route`

試行の範囲で有効なネットワークルートを追加します。

```ts
await browser.route('**/api/quote', async (route) => {
  await route.fulfill({ json: { cents: 4200 } });
});
```

`route.fetch()` は、ルートの処理方法を決定せずに、転送先の `{ url, status, headers, body(), text(), json() }` を返します。対象オリジンが設定済みヘッダーの送信対象なら、そのヘッダーを使います。アクションのタイムアウトが適用されます。ページ遷移のルールを超える可能性があるため、リダイレクトには従いません。

- パターンは文字列または `RegExp` で、どちらも URL 全体と照合します。文字列の `*` はパスの 1 セグメント内、`**` は `/` をまたいで一致し、`?` は任意の 1 文字、`\` は次の文字をエスケープします。`unroute` と `waitForResponse` も同じパターンを使います。
- ルートは `app.restart()`、`app.clearState()`、セッションの復元をまたいでも残ります。
- ルートを設定している間は、ブラウザの HTTP キャッシュを迂回します。そのため、以前のページが読み込んだリソースもルートを通ります。Firefox では、現在のドキュメントがすでに読み込んだ画像やスタイルシートは、リクエストなしで再利用されます。ページを開く前にルートを追加してください。
- `route.request.postData` は、本文のバイト列を UTF-8 としてデコードしたものです。テキストでない本文は、U+FFFD を含む文字列になります。`route.fetch()` は、元のバイト列をそのまま送ります。
- 新しく登録したルートから順に実行します。
- ハンドラーは `fulfill`、`continue`、`fallback`、`abort` のいずれかで、必ず 1 回だけ処理を決定します。それぞれの説明は下の `WebRoute` にあります。
- `continue` の URL は `goto` と同じルールで検証します。`continue` で `undefined` にしたヘッダーは、リダイレクト時も削除します。
- `fulfill` の本文は文字列またはバイト列（`Buffer`、`Uint8Array`）で、そのまま送ります。
- 複数の Cookie を設定するには、`route.fetch()` のヘッダーと同じく、1 つの `set-cookie` ヘッダー内で `\n` で連結します。それ以外のヘッダー内の改行は拒否します。
- ハンドラーが例外をスローすると（リクエストへの `expect` が失敗した場合など）、次のステップをそのエラーで失敗させます。後続のステップがなければ、試行の終了時に失敗させます。リクエストが中断された `goto` など、ハンドラーの失敗によって失敗したステップには、ハンドラーのエラーを使います。ハンドラーが意図的にリクエストを中断した `goto` は `ACTION_FAILED` になります。その時点でまだ動いているハンドラーには、完了までクリーンアップの時間を与えます。その時間を過ぎてからスローされた例外は破棄します。

| エラー | 発生条件 |
| --- | --- |
| `INVALID_ARGUMENT` | パターンに述語関数を渡した場合。また、処理の決定で受け付けないオプション（Playwright の `abort(errorCode)`、誤記したキーなど）がある場合は、リクエストを中断して次のステップを失敗させます。 |
| `ACTION_FAILED` | ハンドラーが処理を 2 回決定したか、決定しなかった場合。 |
| `POLICY_DENIED` | `continue` の URL が禁止スキームを使う場合。 |
| `CLEANUP_TIMEOUT` | ハンドラーがクリーンアップの時間を超えた場合。試行を失敗させます。 |

```ts
/**
 * One of `json`, `body`, or `path`, or none for an empty body. `path` names a
 * file relative to the project root; its `Content-Type` follows its
 * extension unless `contentType` or a `content-type` header sets one.
 */
export type RouteFulfillResponse = {
  status?: number;
  /** Response headers; `set-cookie` may join several cookies with `\n`, as `route.fetch()` reports them. */
  headers?: Record<string, string>;
  /** Sets the `Content-Type` response header. */
  contentType?: string;
} & (
  | { json: JsonValue; body?: never; path?: never }
  | { body: string | Uint8Array; json?: never; path?: never }
  | { path: string; json?: never; body?: never }
  | { body?: never; json?: never; path?: never }
);

/** What `continue` changes about the request before it goes to the network. */
export interface RouteContinueOverrides {
  /** Resolved against the base URL like `goto`; must keep the request's scheme. */
  url?: string;
  /** Request method. */
  method?: string;
  /** Replaces every request header; `undefined` drops one, and the configured `headers` for an allowed origin are added on top. */
  headers?: Record<string, string | undefined>;
  /** Request body. */
  postData?: string;
}

export interface WebRoute {
  /** The intercepted request. */
  readonly request: {
    readonly url: string;
    readonly method: string;
    readonly headers: Readonly<Record<string, string>>;
    readonly postData?: string;
  };
  /** Reads upstream without deciding the route or following redirects. */
  fetch(): Promise<WebResponse>;
  /** Fulfills the intercepted request once. */
  fulfill(response: RouteFulfillResponse): Promise<void>;
  /** Sends the intercepted request to the network once, skipping every other route. */
  continue(overrides?: RouteContinueOverrides): Promise<void>;
  /** Hands the intercepted request to the route registered before this one, or the network when none matches. */
  fallback(): Promise<void>;
  /** Aborts the intercepted request once. */
  abort(): Promise<void>;
}
```

| エラー | 発生条件 |
| --- | --- |

#### `waitForResponse`

[`route`](#route) と同じパターン構文で、一致するレスポンスを待ちます。

```ts
const response = await browser.waitForResponse('**/api/orders');
expect(response.status).toBe(201);
```

- 期限が制限するのは、一致するレスポンスを待つ時間です。ヘッダーが届いた時点で解決します。Firefox では、本文が始まった時点です。
- `body()`、`text()`、`json()` は、それぞれ独自の時間上限で本文を待ちます。`config.actionTimeout` を使い、テストの期限を上限とします。
- `url`、`status`、`headers` は常に読めます。
- 本文が実際に空なら、`body()` は空の `Buffer`、`text()` は `''` を返し、`json()` は拒否します。

| エラー | 発生条件 |
| --- | --- |
| `INVALID_ARGUMENT` | パターンに述語関数を渡した場合。 |
| `ACTION_FAILED` | 期限内に一致するレスポンスがなかった場合。`body()`、`text()`、`json()` では、期限時点でも本文の受信が続いている場合や、ブラウザが本文を読めなかった場合も、空文字列の代わりにこのエラーになります。後者には、宣言された `Content-Length` に達する前の接続リセット、ページが中断したリクエスト、20 MB を超える本文、ブラウザが本文を保持しないリダイレクトが含まれます。 |

```ts
export interface WebResponse {
  /** Response URL. */
  readonly url: string;
  /** HTTP status. */
  readonly status: number;
  /** Response headers, lower-cased names; `route.fetch()` joins several `set-cookie` values with `\n`, `waitForResponse` leaves cookie headers out. */
  readonly headers: Readonly<Record<string, string>>;
  /** Waits for the body and returns its bytes. */
  body(): Promise<Buffer>;
  /** Waits for the body and parses it as JSON. */
  json<T = unknown>(): Promise<T>;
  /** Waits for the body and reads it as text. */
  text(): Promise<string>;
}
```

```ts
await browser.setCookies([{ url: 'http://localhost:3000', name: 'tz', value: 'UTC' }]);
```

- 相対 `url` は、`goto` と同じくベース URL を基準に解決します。
- `domain` 形式では、スキームはベース URL に従い、先頭の `.` は除去します。
- 完全な `url` と `domain` には `app.url` が要らないため、どちらも [`attachBrowser`](#attachbrowser) で使えます。

| エラー | 発生条件 |
| --- | --- |
| `POLICY_DENIED` | 対象をパースできないか、禁止スキームの場合。何も設定しません。 |
| `APP_URL_REQUIRED` | `app.url` のないターゲットで相対 `url` を指定した場合。何も設定しません。 |
| `INVALID_ARGUMENT` | Cookie に `url` も `domain` もない場合。何も設定しません。 |

```ts
export interface CookieFields {
  /** Cookie name. */
  name: string;
  /** Cookie value. */
  value: string;
  /** Unix timestamp in whole seconds. */
  expires?: number;
  /** HttpOnly flag. */
  httpOnly?: boolean;
  /** Secure flag. */
  secure?: boolean;
  /** SameSite attribute. */
  sameSite?: 'Strict' | 'Lax' | 'None';
}

/** `url`, or `domain` with an optional `path`, never both. */
export type Cookie = CookieFields &
  (
    | { url: string; domain?: never; path?: never }
    | { url?: never; domain: string; path?: string }
  );
```

#### `clearCookies`

`clearCookies({ name?, domain?, path? })` は、指定したすべてのフィルターに一致する Cookie を削除します。文字列は完全一致、RegExp はそのフィールドに適用します。オプションなしでは、すべての Cookie を削除します。ほかのストレージは残ります。

```ts
await browser.clearCookies({ name: /^session/, path: '/' });
```

```ts
export interface CookieFilter {
  name?: string | RegExp;
  domain?: string | RegExp;
  path?: string | RegExp;
```

#### `setViewport`

ビューポートのサイズを設定し、新しいサイズをレポートに記録します。

```ts
await browser.setViewport({ width: 390, height: 844 });
await app.open('/');
```

- Playwright の `setViewportSize` と同じく、最初のページ遷移前にも使えます。次の `app.open` はそのサイズで読み込むため、スマートフォンサイズのテストが先にデスクトップレイアウトを描画することはありません。
- サイズは、`app.restart()` と `app.clearState()` をまたいで、試行の残りの期間維持します。

#### `onDialog`

試行内で有効なネイティブダイアログのハンドラーを登録し、登録解除の関数を返します。

```ts
const off = await browser.onDialog('accept');
await screen.getByRole('button', 'Delete').tap();
await off();
```

- ハンドラーは `'accept'`、`'dismiss'`、または `Dialog` を受け取る関数です。
- 関数ハンドラーは `accept` または `dismiss` を呼ぶ必要があります。どちらも呼ばなければ、未処理のダイアログと同じく閉じます。
- ハンドラーが例外をスローすると、次のステップをそのエラーで失敗させます。後続のステップがなければ、試行の終了時に失敗させます。応答前にスローした場合は、ダイアログを閉じます。

エラーは `onDialog` ではなく、次のステップに現れます。

| エラー | 発生条件 |
| --- | --- |
| `APP_NOT_OPEN` | 関数ハンドラーがどちらの応答もしなかったか、ダイアログを処理するハンドラーがなかった場合。 |
| `ASSERTION_FAILED` | ハンドラーの `expect` が失敗した場合。 |
| `ENGINE_FAILURE` | ハンドラーが未分類のエラーをスローした場合。 |

```ts
/** A native dialog as a test's handler sees it. */
export interface Dialog {
  /** The native dialog kind, independent of its message. */
  readonly type: 'alert' | 'confirm' | 'prompt' | 'beforeunload';
  /** The dialog's text. */
  readonly message: string;
  /** Accepts the dialog once. */
  accept(text?: string): Promise<void>;
  /** Dismisses the dialog once. */
  dismiss(): Promise<void>;
}

export type DialogHandler = 'accept' | 'dismiss' | ((dialog: Dialog) => void | Promise<void>);
```

#### タブ

`target="_blank"` のリンクや `window.open` からアプリが開くタブは、バックグラウンドで開きます。アクティブなタブは変わらず、`screen`、`expect`、`browser` のページ操作は引き続きそのタブを対象にします。`waitForPopup` は、トリガーが開いたタブをアクティブにします。アクティブなタブが閉じると、それを開いたタブに戻ります。そのタブもなければ、開いているタブのうち最後にアクティブだったものに戻ります。

```ts
const popup = await browser.waitForPopup(() =>
  screen.getByRole('button', 'Open verification tab').tap(),
);
const code = await screen.getByText(/^TAB-/).textContent();
await popup.close(); // the opener is active again
await screen.getByRole('textbox', 'Verification code').fill(code);
```

- `waitForPopup(trigger)` はトリガーを実行し、開いたタブがアクティブになると、そのタブを返します。待機開始後に最初に現れたタブを取得します。以前の操作で開かれ、今になってページが読み込まれたタブが対象になることもあります。
- `tabs()` は開いた順にタブを返し、試行中は同じタブに同じ `BrowserTab` を返します。最初のページを読み込んだ時点で一覧に加わるため、1 つの操作で 2 タブが開くと、ページの読み込み順に並びます。ページを持たないタブは一覧に載りません。ダウンロード、`mailto:` アドレス、内容のないレスポンスへ向かう `target="_blank"` リンクなどが該当します。
- `tab.activate()` は、ほかのタブを閉じずにそのタブをアクティブにします。`tab.close()` はタブを閉じ、アクティブだった場合は次のタブがアクティブになるまで待ちます。
- `newTab()` は、同じ Cookie とストレージを持つ同一ブラウザコンテキストに空のタブを開き、アクティブにします。`goto` で遷移してください。
- 読み込み前に開き元が閉じたタブも一覧に載ります。
- スクリーンキャストはアクティブなタブを記録し、切り替わるごとに動画セグメントを分けます。自分自身を閉じるタブは、録画を保存する前にページが閉じると、セグメントを失います。プロバイダー自身の録画は、すべてのタブを対象にします。

```ts
/** One tab of the browser the attempt drives. */
export interface BrowserTab {
  url(): Promise<string>;
  title(): Promise<string>;
  /** Whether this is the active tab. */
  isActive(): boolean;
  isClosed(): boolean;
  /** Makes this the active tab. */
  activate(): Promise<void>;
  /** Closes the tab; the tab that opened it becomes active when it was. */
  close(): Promise<void>;
}
```

| エラー | 発生条件 |
| --- | --- |
| `ACTION_FAILED` | `waitForPopup`: 時間内にタブが開かなかった場合。トリガーが時間内に解決した場合は `no tab opened within <n>ms; the trigger resolved after <m>ms`、タブが最初のページをまだ読み込み中なら `the tab the app opened did not load <url> within <n>ms` になります。`activate`: タブが閉じている場合。 |

#### `waitForDownload`

トリガーを実行し、それが開始するダウンロードを待ちます。

```ts
const file = await browser.waitForDownload(() =>
  screen.getByRole('link', 'Export CSV').tap(),
);
```

- ファイルを `download` アーティファクトとして登録し、相対 `path`、ランナー側の `absolutePath`、`suggestedFilename` を返します。
- ファイル API で内容を調べるには `absolutePath` を使います。
- 待機時間には、トリガー自体の実行時間も含みます。

| エラー | 発生条件 |
| --- | --- |
| `UNSUPPORTED_CAPABILITY` | ブラウザが、[`downloads`](/browser#downloads-on-the-provider) のないブラウザプロバイダーのものである場合。 |
| `ACTION_FAILED` | 時間内にダウンロードが完了しなかった場合。トリガーは時間内に解決したもののダウンロードを開始しなかった場合は、`no download started within <n>ms; the trigger resolved after <m>ms` になります。 |

タイムアウト時にトリガーがまだ動いていれば、ステップのタイムアウトになります。トリガーが例外をスローした場合は、そのエラーで失敗します。

#### `waitForDownloads`

`waitForDownloads(trigger, { count })` はトリガーを 1 回呼び、同じタイムアウトの範囲内で、開始順に `count` 個のファイルを返します。それぞれが独立したアーティファクトです。時間内に開始した数が足りなければ、期待数と実際の数をエラーに表示します。余分なダウンロードは無視します。

#### `keyboard`

フォーカスのある場所へ、ビューポート単位でキーボード入力を送ります。

```ts
await browser.keyboard.press('Escape');
await browser.keyboard.type('hello');
```

- `type(text)` が入力するのは通常のテキストだけで、`Secret` は使えません。絵文字、アクセント付きの文字、タブなど、キーで入力できない文字は、フォーカスのあるフィールドに挿入します。カスタムウィジェットなど、フォーカスのある要素がキーを受け付けてもテキストを受け付けない場合、呼び出しは失敗します。ボタンやリンクにフォーカスがある場合、または何にもフォーカスがない場合、その文字は入力しません。そこでキーを押しても何も入力されないのと同じです。`keyboard.down` で Shift を押したままでも、テキストは書かれたとおりに入力されます。
- 対象がある場合は、`locator.press` と `locator.fill` を優先してください。
- 各メソッドの説明は [`Browser`](#browser-interface) にあります。

#### `mouse`

エージェントの観測とは独立して、テストコードからビューポート単位のポインター入力を行います。

```ts
await browser.mouse.move(120, 240);
await browser.mouse.down();
await browser.mouse.move(320, 240);
await browser.mouse.up();
```

ビューポート外の座標は `INVALID_ARGUMENT` をスローします。`wheel` を含む各メソッドの説明は [`Browser`](#browser-interface) にあります。

#### `attachBrowser`

`attachBrowser(cdpEndpoint: string, options?: AttachBrowserOptions)` は、テストの外で、すでに動いている Chromium に接続します。テストが受け取るものと同じ `browser` と `screen` を返します。

```ts title="scripts/sign-in.ts"
import { attachBrowser } from '@e2e-dev/web';

await using attached = await attachBrowser('http://127.0.0.1:9222');
const { browser, screen } = attached;
await browser.goto('http://localhost:3000/login');
await screen.getByLabel('Email').fill('qa@example.com');
await screen.getByRole('button', 'Sign in').tap();
```

- `cdpEndpoint` は、DevTools の HTTP エンドポイント、またはその `ws://` URL です。Chromium 専用です。
- macOS では、Chrome を `--use-mock-keychain` 付きで起動してください。付けないと、Chrome for Testing がキーチェーンのプロンプトを待ち、ページを読み込まないことがあります。
- ブラウザがデフォルトのコンテキストで表示しているタブを操作します。タブが 1 つだけならそのタブ、複数あれば表示中のタブです。開いているタブがなければ、1 つ開きます。
- 相対 URL には基準がありません。`browser.goto` には完全な URL を渡してください。
- `close()` は接続を切り離します。ブラウザは、タブ、Cookie、ストレージを保ったまま動き続けます。閉じるのは、接続時に開いたタブと、接続中にページが開いたタブだけです。接続がブラウザに設定した内容（ビューポート、メディア、権限）は元に戻します。`close()` は冪等で、`await using` でも実行され、失敗があれば、それらをまとめた `AggregateError` をスローします。
- `timeout` は、接続とすべての操作を合わせた時間を制限します。使い切ると、それぞれが `TEST_TIMEOUT` で失敗します。
- `app` はないため、タブの再起動、状態のクリア、セッションの保存を行うものはありません。

| オプション | 型 | デフォルト |
| --- | --- | --- |
| `testIdAttribute` | `string` | `'data-testid'` |
| `timeout` | `number` | `120000` |
| `signal` | `AbortSignal` | - |

- `timeout` は、すべての操作を合わせた時間上限をミリ秒で指定します。接続の時点から数えます。1 から 2147483647 までの整数で指定します。それ以外の値は `INVALID_ARGUMENT` をスローします。
- `signal` は、接続とすべての操作をキャンセルします。その場合も `close()` は接続を切り離します。

```ts
interface AttachedBrowser extends AsyncDisposable {
  readonly browser: Browser;
  readonly screen: Screen;
  /** Detaches. The browser keeps running, with its tabs, cookies, and storage. */
  close(): Promise<void>;
}
```

## ブラウザのインストール

エンジンは固定したビルドで動きます。`chromium` には Chrome for Testing 157.0.8103.38（ヘッドレス実行にはヘッドレスシェル、headed 実行には完全版の Chrome）、`firefox` には Firefox 159.0.1 を使います。ブラウザがなければ、実行時間の計測開始前に、1 回の実行につき 1 回ダウンロードします。CI やコンテナイメージで独立した手順としてインストールするには、パッケージのコマンドを使ってください。

<CodeGroup>
```bash npm
npx @e2e-dev/web install chromium --with-deps
```

```bash pnpm
pnpm exec e2e-web install chromium --with-deps
```

```bash bun
bunx @e2e-dev/web install chromium --with-deps
```
</CodeGroup>

- `chromium`、`firefox`、`ffmpeg` のいずれか、または複数を指定できます。省略すると `chromium` をインストールします。
- `--headed` は、ヘッドレスシェルの代わりに、headed 実行が起動する完全版の Chrome をインストールします。両方を使うには、両方のコマンドを実行してください。
- `--with-deps` は、Debian と Ubuntu でブラウザが必要とするシステムライブラリも、`apt-get` でインストールします。root で実行していない場合は `sudo` を通します。
- ブラウザの保存先は `E2E_BROWSERS_PATH`、なければユーザーキャッシュです。macOS では `~/Library/Caches/e2e/browsers`、Linux では `$XDG_CACHE_HOME/e2e/browsers` または `~/.cache/e2e/browsers`、Windows では `%LOCALAPPDATA%\e2e\browsers` です。マシン上のすべてのプロジェクトが共有し、同時に実行したインストールは互いの完了を待ちます。
- ダウンロード元は `storage.googleapis.com`（Chrome for Testing）、`archive.mozilla.org`（Firefox）、`github.com`（ffmpeg）です。`E2E_BROWSERS_DOWNLOAD_HOST` には、`https://mirror.example.com` のように、同じパスで配信するミラーを指定します。暗号化なしの `http` は `localhost` でだけ使えます。ミラーを使うかどうかにかかわらず、すべてのアーカイブは固定された SHA-256 と一致する必要があります。
- ダウンロードは、`NO_PROXY` のホストを除き、`HTTPS_PROXY` または `HTTP_PROXY` を経由します。Node 22 と Node 24 の初期リリースでは、`NODE_USE_ENV_PROXY=1` も設定してください。
- Linux では、Firefox を `tar` と `xz` で展開します。`--with-deps` は `xz-utils` をインストールします。
- `chromium` の動画には、`libvpx-vp9` を持つ ffmpeg が必要です。エンジンは `E2E_FFMPEG_PATH`、なければブラウザキャッシュ内の固定ビルド、それもなければ `PATH` 上の `ffmpeg` を使います。いずれもない場合は、最初の録画時に固定ビルドをブラウザキャッシュへダウンロードします。事前にインストールするには `install ffmpeg` を使います。
- インストールが失敗すると、コマンドは 0 以外で終了します。Ctrl-C または SIGTERM はダウンロードを中止し、途中までのファイルを削除して、130 または 143 で終了します。

### `WebOptions`

```ts
/**
 * Options of the browser engine: how it drives the app. The app itself
 * (its `url`, `environment`, `identity`, and the command that starts it) is
 * the target's `app`.
 */
export interface WebOptions {
  /**
   * Browser to launch, `chromium` (default) or `firefox`, driven over
   * WebDriver BiDi. A `BrowserProvider` leases hosted browsers instead, each
   * attached to over CDP: one per worker slot, released when the run ends,
   * or one per attempt with `scope: 'attempt'`. A provider implies chromium
   * and excludes `connect`.
   */
  readonly browser?: BrowserName | BrowserProvider;
  /**
   * Initial viewport of every attempt's page; default 1280 by 720. `null`
   * emulates no size: the page fills the browser window, whatever size the
   * window has (a hosted browser's live view, a headed run), and
   * `browser.setViewport` still fixes one for the rest of the attempt.
   */
  readonly viewport?: ViewportSize | null;
  /**
   * How the engine's own screencast records an attempt that records video.
   * A browser provider that records (`BrowserProvider.record`) records in
   * its place, and ignores these. Which attempts record is the config's
   * `video`, not an engine option.
   */
  readonly screencast?: WebScreencastOptions;
  /**
   * Attach to a remote browser over CDP instead of launching locally. Requires
   * the chromium browser (the default). Wired by a hosted-browser engine.
   */
  readonly connect?: WebConnectOptions;
  /**
   * Headers added to every request that starts at the app's origin (the
   * scheme, host, and port of `app.url`) or one in `credentialOrigins`.
   * Useful for preview-protection tokens. A request that starts at another
   * origin goes without them; a redirect keeps them, to any origin.
   * Names are case-insensitive and replace existing headers of the same name.
   * Setting them blocks service workers.
   */
  readonly headers?: Readonly<Record<string, string>>;
  /**
   * HTTP basic authentication. The browser answers a `401` challenge from the
   * app's origin, or one in `credentialOrigins`, with these credentials.
   */
  readonly basicAuth?: WebBasicAuth;
  /**
   * More origins that receive `headers` and `basicAuth`, such as
   * `https://api.example.com`; requires `headers` or `basicAuth`.
   */
  readonly credentialOrigins?: readonly string[];
  /**
   * The attribute that carries an element's test id: what the `testId` query
   * (`screen.getByTestId`) resolves and what `SemanticNode.testId` reports.
   * Defaults to `data-testid`.
   */
  readonly testIdAttribute?: string;
  /**
   * The `User-Agent` every attempt's context sends and `navigator.userAgent`
   * reports, for an app that switches into a test mode on a marker in the
   * agent string. Defaults to the browser's own. A `user-agent` entry in
   * `headers` beside it is `INVALID_CONFIG`.
   */
  readonly userAgent?: string;
  /**
   * The locale every attempt's context runs in, a BCP 47 tag such as
   * `de-DE`: what `navigator.language`, `Intl` formatting, and the
   * `Accept-Language` header report. Defaults to the browser's own. An
   * `accept-language` entry in `headers` beside it is `INVALID_CONFIG`.
   */
  readonly locale?: string;
  /**
   * The IANA time zone every attempt's context runs in, such as
   * `Europe/Berlin`: what `Date` and `Intl` resolve local time against.
   * Defaults to the machine's.
   */
  readonly timezoneId?: string;
  /** The `prefers-color-scheme` every page reports. See [Media emulation](#media-emulation). */
  readonly colorScheme?: WebMedia['colorScheme'];
  /** The `prefers-reduced-motion` every page reports. See [Media emulation](#media-emulation). */
  readonly reducedMotion?: WebMedia['reducedMotion'];
  /** Scripts every document runs before the page's own. See [Init scripts](#init-scripts). */
  readonly initScripts?: readonly WebInitScript[];
}
```

### `Browser` インターフェース

```ts
/**
 * The browser the attempt drives, showing one active tab. Navigation, reads,
 * `locator`, `frameLocator`, `evaluate`, `waitForResponse`, `waitForDownload`,
 * the keyboard and mouse, `expect(browser)`, and `screen` act on the active
 * tab; cookies, routes, and dialog handlers cover the whole browser, every
 * tab included. A tab the app opens (a `target="_blank"` link,
 * `window.open`) joins `tabs()` but does not become active on its own:
 * `waitForPopup` makes the tab its trigger opens active, and `activate`
 * any other. When the active tab closes, the tab that opened it is active
 * again.
 */
export interface Browser extends Expectable<BrowserExpectation> {
  /** Navigates to an allowed URL. */
  goto(
    url: string,
    options?: {
      waitUntil?: 'load' | 'domcontentloaded' | 'networkidle';
      timeout?: number;
    },
  ): Promise<void>;
  /** Reloads the current document. */
  reload(options?: ActionOptions): Promise<void>;
  /** Navigates browser history back once. */
  back(options?: ActionOptions): Promise<void>;
  /** Navigates browser history forward once. */
  forward(options?: ActionOptions): Promise<void>;
  /** Returns the current URL. */
  url(): Promise<string>;
  /** Returns the current title. */
  title(): Promise<string>;
  /** Waits for the current URL to match. */
  waitForURL(url: string | RegExp, options?: { timeout?: number }): Promise<void>;
  /** Creates a web-only CSS or XPath locator. */
  locator(selector: string): Locator;
  /** Creates a screen query scope inside one iframe. */
  frameLocator(selector: string): FrameScreen;
  /** Evaluates trusted test code in the page: a function, or a string expression whose value is returned, called first if it is a function. */
  evaluate<T extends JsonValue>(fn: string | (() => T | Promise<T>)): Promise<T>;
  /** Evaluates trusted test code with one required JSON-safe argument. */
  evaluate<T extends JsonValue, Arg extends JsonValue>(
    fn: string | ((arg: Arg) => T | Promise<T>),
    arg: Arg,
  ): Promise<T>;
  /** Adds a script every document runs before the page's own, from the next navigation on. */
  addInitScript(script: string | { path: string } | (() => unknown)): Promise<void>;
  /** Adds an init script function called with one JSON argument. */
```
