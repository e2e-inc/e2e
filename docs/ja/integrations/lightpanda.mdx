[Lightpanda](https://lightpanda.io) は、Chromium を使わずにゼロから開発されたオープンソースのヘッドレスブラウザです。
ミリ秒単位で起動し、Chrome より大幅に少ないメモリーで動作し、Chrome DevTools Protocol に対応しています。
`@e2e-dev/lightpanda` の `lightpanda()` は、その [ブラウザプロバイダー](/browser#hosted-browsers) です。
実行開始時に、ワーカースロットごとに専用の `lightpanda serve` を空きポートで起動し、終了時に停止します。

<Note>
Web エンジンは Lightpanda でページを開けません。ページを開くテストはタイムアウトします。
[使えない機能](#what-does-not-work) を参照してください。
</Note>

## セットアップ

パッケージをインストールします。

<CodeGroup>
```bash npm
npm install --save-dev @e2e-dev/lightpanda
```

```bash pnpm
pnpm add -D @e2e-dev/lightpanda
```

```bash bun
bun add -d @e2e-dev/lightpanda
```
</CodeGroup>

プロバイダーが起動する Lightpanda の nightly バイナリもインストールします。

<CodeGroup>
```bash macOS
brew install lightpanda-io/browser/lightpanda
```

```bash Linux
curl -L -o lightpanda https://github.com/lightpanda-io/browser/releases/download/nightly/lightpanda-x86_64-linux
install -D -m 755 lightpanda ~/.local/bin/lightpanda
```
</CodeGroup>

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { lightpanda } from '@e2e-dev/lightpanda';

export default {
  targets: [
    {
      name: 'lightpanda',
      engine: web({ browser: lightpanda() }),
      app: { url: 'http://localhost:3000' },
    },
  ],
} satisfies E2EConfig;
```

プロバイダーは、`PATH`、`~/.lightpanda/lightpanda`、`~/.local/bin/lightpanda` から `lightpanda` を探します。
これらは [agent-browser](https://agent-browser.dev/engines/lightpanda) も検索する場所です。
`e2e run` の起動環境の `LIGHTPANDA_PATH`、またはオプションの `binary` でバイナリを指定することもできます。
見つからなければテスト開始前に実行が失敗し、インストールページが案内されます。
各ワーカーに専用サーバーがあるため、`workers` が同時起動数を決めます。各サーバーは実行ログに表示されます。

```text
ℹ lightpanda (1 of 2): lightpanda 1.1.0-nightly at ws://127.0.0.1:51165/
```

## 起動済みサーバーに接続する

CI の Docker イメージなど、すでに動いている Lightpanda には、プロバイダーではなく
[`connect`](/reference/web#options) を使うターゲットとして接続します。
エンジンは CDP エンドポイントに接続し、実行終了時もサーバーを停止しません。

```ts title="e2e.config.ts"
web({ connect: { cdpEndpoint: () => process.env.LIGHTPANDA_URL ?? 'ws://127.0.0.1:9222/' } })
```

```bash
docker run -d --name lightpanda -p 127.0.0.1:9222:9222 lightpanda/browser:nightly
```

この場合、全ワーカーが同じサーバーを共有します。
1 つの `lightpanda serve` が受け付ける接続数はデフォルトで 16 です。
それ以上で実行する場合は、`--cdp-max-connections` を `workers` より大きくしてください。

## オプション

| オプション | デフォルト | 意味 |
| --------------- | ------------------------------- | ------- |
| `binary` | `LIGHTPANDA_PATH`、なければ検索 | 起動するバイナリ。パス、または `PATH` 上の名前。 |
| `loadResources` | `[]` | サーバーが取得するサブリソース。`iframe`、`image`、`stylesheet`。[ページの追加リソースを取得する](#fetch-more-of-the-page) を参照。 |
| `args` | `[]` | プロバイダーが設定するフラグの後に渡す、追加の `lightpanda serve` フラグ。 |

プロバイダーは実行中、ワーカースロットごとに 1 サーバーを保持します。
サーバーが 10 秒以内にポートで応答しない場合や、それより先にバイナリが終了した場合は取得に失敗します。
後者では stderr がメッセージに含まれます。

## ページの追加リソースを取得する

`lightpanda serve` はデフォルトでは画像、外部スタイルシート、iframe などのサブリソースを要求しません。
`loadResources` で個別に有効にすると、サーバーに `--load-resources` として渡されます。

```ts
web({ browser: lightpanda({ loadResources: ['stylesheet', 'iframe'] }) })
```

## 使える機能

動作するのは、ページを必要としない機能だけです。
2026 年 11 月の Lightpanda nightly（`1.1.0-nightly.12226`）で e2e testbed のローカルスイートを実行すると、
次のところまで動作します。

- プロバイダーはワーカースロットごとに 1 サーバーを起動し、実行終了時に停止します。
- `fetch` で API を呼び出すテストなど、ページを開かないテストは成功します。

## 使えない機能

プロバイダーを使う場合も [`connect`](#attach-to-a-running-server) を使う場合も、ページを開くテストは成功しません。
クエリ、操作、アサーション、[エージェントステップ](/agent-steps) は、いずれもページを必要とします。

| 機能 | 動作 | 理由 |
| ------- | ------------ | --- |
| ページを開く操作：`app.open`、`browser.goto` | 呼び出しが戻りません。テストは [`timeout`](/reference/config#timeout) に達すると、`TEST_TIMEOUT` または `ACTION_FAILED` で失敗します。 | Lightpanda は、エンジンが読み取る形式では新しいページを報告しません。 |
| [セッション](/authentication)（`test.setup` と `session.save`、テストの `session:`） | セットアップが同じようにタイムアウトし、e2e はそのセッションを使う各テストをスキップします。 | セットアップがページを開けません。 |

修正には Lightpanda 側の変更が必要です。
代わりに、Chromium ターゲットでスイートを実行してください。
