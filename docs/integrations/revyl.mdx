`@e2e-dev/revyl` is a hosted device provider for the mobile engine.
It starts a Revyl device for each worker, installs your app on it, and releases the device when the run ends.
Use the standard `app`, `screen`, and `expect` APIs to test your app's user flows.
For websites, `revylBrowsers()` from `@e2e-dev/revyl/web` is a
[browser provider](/reference/web#hosted-browsers) that runs each test in Chrome on
Revyl ([Run web targets in browsers](#run-web-targets-in-browsers)).
For macOS apps, `revylDesktop()` from `@e2e-dev/revyl/desktop` runs the
[desktop engine](/desktop) on a Revyl Mac computer
([Run desktop targets on Revyl Macs](#run-desktop-targets-on-revyl-macs)).

## Install and authenticate

Install the integration alongside the mobile engine:

<CodeGroup>
```bash npm
npm install --save-dev e2e @e2e-dev/mobile @e2e-dev/revyl
```

```bash pnpm
pnpm add -D e2e @e2e-dev/mobile @e2e-dev/revyl
```

```bash bun
bun add -d e2e @e2e-dev/mobile @e2e-dev/revyl
```
</CodeGroup>

Set `REVYL_API_KEY` in the environment that starts e2e. In CI, store it as
a secret. Without it, the lease fails before any test starts.

The test runner needs only Node.js and the package dependencies: no Mac,
Xcode, or Android SDK. Build your app separately, as a zipped iOS simulator
`.app` or an Android `.apk`, and host it at an `https` URL Revyl can download.

## Configure a target

Set `device: revyl({ app, device })` on the mobile engine. `app` is the build's
`https` URL, and `device` is a model from Revyl's catalog. To test a local
build instead, leave `app` out and set the target's `app.appPath`.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';
import { revyl } from '@e2e-dev/revyl';

export default {
  targets: [
    {
      name: 'ios',
      engine: mobile({
        platform: 'ios',
        device: revyl({ app: 'https://builds.example.com/MyApp-simulator.zip', device: 'iPhone 17 Pro Max', osVersion: 'iOS 27.0' }),
      }),
      app: { bundleId: 'com.example.app' },
    },
    {
      name: 'android',
      engine: mobile({
        platform: 'android',
        device: revyl({ app: 'https://builds.example.com/app.apk', device: 'Pixel 7' }),
      }),
      app: { bundleId: 'com.example.app' },
    },
  ],
  workers: 2,
  assertionTimeout: 15_000,
} satisfies E2EConfig;
```

Revyl installs `app` when it starts each device, so leave `app.appPath` off
the target. For Android, `bundleId` is the app's package name.

Without `app`, each device starts with no app, and the device provider uploads
the target's `app.appPath` to it and installs it there: a zipped iOS
simulator `.app` or an Android `.apk`. Do not also call `device.installApp()`
for that build, because that uploads it a second time.

```ts title="e2e.config.ts"
{
  name: 'android-local',
  engine: mobile({ platform: 'android', device: revyl({ device: 'Pixel 7' }) }),
  app: { appPath: './build/app-debug.apk', bundleId: 'com.example.app' },
}
```

A screen read on a Revyl device takes about 2.5 s (occasionally over 5 s),
so set `assertionTimeout` to `15_000`. With the default 5 s, an `expect` can
time out before it even reads the screen once.

## Test an app flow

Tests use the same mobile APIs as on any other device, except the ones under [Limits](#limits):

```ts title="tests/checkout.e2e.ts"
import { expect } from 'e2e';
import { test } from '@e2e-dev/mobile';

test('opens the cart', async ({ app, screen }) => {
  await app.open();
  await screen.getByText('Cart').click();
  await expect(screen.getByText('Your cart is empty')).toBeVisible();
  await app.screenshot('cart');
});
```

## Choose device options

| Option | Default | Purpose |
| --- | --- | --- |
| `app` | none, so the target's `app.appPath` is installed | `https` URL of the build. A local path is refused, since Revyl cannot read it; use `app.appPath` for a local build. |
| `device` | required | Device model as Revyl lists it, such as `iPhone 17 Pro Max` or `Pixel 7`. |
| `osVersion` | Revyl's default for the model | OS version as Revyl lists it, such as `iOS 27.0` or `Android 14`. |

Unknown or invalid options fail config load with `INVALID_CONFIG`.

## Limits

- Keep `workers` within the number of concurrent devices your Revyl plan allows.
- A device runs from lease until release. The engine releases every acquired
  device when the run finishes or is interrupted.
- If the runner is killed before it releases a device, nothing sends the
  session another command, and Revyl ends it after 5 minutes idle.
- A release fails the run when agent-device can't confirm it ended the
  session, even when every test passed. This happens when Revyl session
  cleanup fails (with more than 20 seconds of `cleanupTimeout` remaining) or
  goes unconfirmed across daemon stop, or when the daemon exits during the run.
  On Windows, ending the session before daemon stop also requires more than
  20 seconds of remaining `cleanupTimeout` (keep the default 30 seconds).
- `app` must be reachable over `https` without credentials in the URL. A
  presigned storage URL works. Set `app` or `app.appPath`, not both.
- An `app.appPath` build is uploaded to each device's own session, so a run
  with `workers: 4` uploads it four times. To upload a large build once, host
  it at an `https` URL and pass that as `app`.
- The app runs on Revyl's network, not yours, and port reverse is not
  available, so it cannot reach `localhost` or a server on your network.
  Point it at a server it can reach over `https`.
- Revyl devices do not record video: an attempt that records one, such as
  with `--video`, fails with `UNSUPPORTED_CAPABILITY`. Use `app.screenshot()`
  for evidence instead.
- Revyl enters text at a point. Use `fill`. `pressSequentially` and typing
  into the focused field fail with `UNSUPPORTED_CAPABILITY`.
- `setAppearance` and `setPermission` work on both platforms, but Revyl's
  iOS simulators refuse the `camera` and `notifications` permissions.
  `setOrientation` turns an Android device to all four sides, and an iOS
  device to `portrait` and `landscape-left` only. `setLocation` works on
  iOS, and `clearKeychain` works on iOS only.
- These `device` methods fail with `UNSUPPORTED_CAPABILITY`: `setNetwork`,
  `setAirplaneMode`, `setLocation` on Android, `clearLocation`,
  `setBiometrics`, `enrollBiometrics`, `clipboard`, and `setClipboard`.
  `foregroundApp` fails on Android, and `back` fails on iOS.

## Run web targets in browsers

`revylBrowsers()` starts a Revyl web session for each test attempt and
attaches the web engine to its Chrome over CDP, so web tests use the same
`app`, `screen`, `browser`, and `expect` APIs as on a local browser.

Install the integration alongside the web engine:

<CodeGroup>
```bash npm
npm install --save-dev e2e @e2e-dev/web @e2e-dev/revyl
```

```bash pnpm
pnpm add -D e2e @e2e-dev/web @e2e-dev/revyl
```

```bash bun
bun add -d e2e @e2e-dev/web @e2e-dev/revyl
```
</CodeGroup>

Create a Web app in Revyl, for example with
`revyl app create --name "My site" --platform web`, and pass its id as `app`.
`url` is the page each session opens on; Revyl registers it as a build of
the app and checks that it loads before the test starts. Set the engine's
`viewport` to `null` and give the session's size to `revylBrowsers()`
instead, since a Revyl browser keeps the size its session opened with:

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { revylBrowsers } from '@e2e-dev/revyl/web';

export default {
  targets: [
    {
      name: 'revyl',
      engine: web({
        browser: revylBrowsers({ app: '<Revyl Web app id>', url: 'https://staging.example.com', viewport: { width: 1280, height: 800 } }),
        viewport: null,
      }),
      app: { url: 'https://staging.example.com' },
    },
  ],
} satisfies E2EConfig;
```

The reporter logs `session <id>, watch at <link>` for each session. The
link opens the session in Revyl, live while the test runs, and needs a
Revyl sign-in. With `REVYL_API_URL` set, it logs `session <id>` alone.

| Option | Default | Purpose |
| --- | --- | --- |
| `app` | required | Id of the Revyl Web app the sessions run under. |
| `url` | required | `http(s)` URL each session opens on, without credentials in it. Revyl must be able to load it. |
| `viewport` | `{ width: 1280, height: 800 }` | `{ width, height }` in CSS pixels, 320 to 3840 by 240 to 2160. The browser keeps it for the whole session. |
| `idleTimeoutSeconds` | `600` | Seconds without activity before Revyl ends a session the run left open, at least 60. |

Unknown or invalid options fail config load with `INVALID_CONFIG`.

### Web limits

- Every attempt, retries included, starts a new session, on the session's
  one browser context and its first tab. Each test pays for a session start,
  and the [limits of a per-attempt lease](/reference/web#pick-a-lease-scope) apply.
- The web engine's `viewport` must be `null`. Revyl refuses to resize the
  browser: `browser.setViewport` fails at once, and a set engine `viewport`
  leaves the attempt waiting until the test times out.
- The CDP URL works once. A dropped connection is not reattached, and the
  attempt fails; a retry starts a new session.
- An attempt that records video, such as with `--video`, gets Revyl's own
  recording of the session as `video/recording.mp4`. Revyl publishes it only
  once the session ends, so stopping a recording ends the session. In a test
  with `video: 'off'` that calls `app.startRecording()`, the
  `app.stopRecording()` call ends the session, and the rest of the test has
  no browser.
- Downloads are unavailable: Revyl's browser refuses them.
- The site runs on Revyl's network, so point `url` and `app.url` at a
  deployed URL, not `localhost`.
- When an attempt ends, on every exit path, the provider stops its session.
  When the run ends, it stops the session of any worker that died before it
  could. If the run itself dies, Revyl ends each session after
  `idleTimeoutSeconds` without activity.

## Run desktop targets on Revyl Macs

`revylDesktop()` runs the [desktop engine](/desktop) on a Revyl Mac
computer and drives it from the runner, so desktop tests use the same
`app`, `screen`, and `expect` APIs as on your own Mac. The runner can run
on any OS.

Install the integration alongside the desktop engine:

<CodeGroup>
```bash npm
npm install --save-dev e2e @e2e-dev/desktop @e2e-dev/revyl
```

```bash pnpm
pnpm add -D e2e @e2e-dev/desktop @e2e-dev/revyl
```

```bash bun
bun add -d e2e @e2e-dev/desktop @e2e-dev/revyl
```
</CodeGroup>

Use `revylDesktop()` as the target's engine. It takes the
[desktop engine's options](/desktop) too:

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { revylDesktop } from '@e2e-dev/revyl/desktop';

export default {
  targets: [
    {
      name: 'mac',
      engine: revylDesktop({ computer: process.env.REVYL_COMPUTER_ID }),
      app: { bundleId: 'com.apple.calculator' },
    },
  ],
} satisfies E2EConfig;
```

Import `test` from `@e2e-dev/desktop` as usual. Without `computer`, each
run creates a Mac and stops it when the run ends, and Revyl then deletes it.
With the id of a persistent Revyl computer, the run uses that one. If it's
running, the run leaves it running. If it's stopped, the run starts it and
stops it again at the end, which keeps its disk. A computer keeps what the
first run on it set up, so later runs on it start faster.

| Option | Default | Purpose |
| --- | --- | --- |
| `computer` | none | Id of a persistent Revyl computer to run on. A blank id, as an unset variable reads, names none. |
| `lifetimeSeconds` | `3600` | Seconds a computer the run creates or starts lives at most, 300 to 86400. Revyl stops it then even when the run can't. |

Unknown or invalid options fail config load with `INVALID_CONFIG`.

When the run starts, the provider sets up the Mac:

1. It installs `@e2e-dev/desktop` and `@e2e-dev/core` with npm, at the
   versions your project has. Those versions must be on the npm registry.
   This happens once per version on each computer.
2. It gives the Mac's `node` Accessibility and Screen Recording, by
   writing the Mac's TCC database with `sudo`.
3. It starts a relay under a LaunchAgent in the Mac's desktop session.
   The engine runs there.

The run's `app.appPath` build is uploaded to the Mac, and a computer keeps
one copy of each build.

### Desktop limits

- Revyl reaches a computer only through short commands, one at a time, so
  each engine call takes a round trip of about 1.5 seconds. On Revyl, a tap
  takes about 3 seconds, and a test runs several times slower than on your
  own Mac.
- The `desktop` fixture (`windows()`, `window()`, `waitForWindow()`,
  `keyboard`, `closeApp()`) works only in the engine's own process, so a
  test on Revyl can't use it. Use `screen`, `app`, and `expect`.
- An `appPath` build is uploaded 64 KiB at a time, about 1.5 seconds per
  piece, so a large build takes minutes the first time a computer gets it.
- One run at a time per computer. A run ends any engine an earlier run left
  on the computer, so two runs on the same persistent computer stop each
  other.
- The engine on the Mac receives the run's environment, as any
  [engine server](/engine-servers) does, through Revyl's API.
- `e2e doctor` creates or starts a computer to check, like a run does.
- When the run ends, the provider stops each computer it created or
  started. If the run itself dies, Revyl stops the computer after
  `lifetimeSeconds`, and the next run on the same machine stops it sooner.
