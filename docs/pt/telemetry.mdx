A CLI `e2e` envia dados de uso anônimos: quais comandos, engines e recursos
as pessoas usam, e onde as execuções falham. A telemetria vem ligada por
padrão. Ela envia contagens e versões, nunca conteúdo de testes, conteúdo do
app ou credenciais.

## Desativação

Qualquer um destes desliga a telemetria:

<CodeGroup>
```bash npm
npx e2e telemetry disable   # saved in ~/.config/e2e/telemetry.json
export E2E_TELEMETRY_DISABLED=1          # for a shell or a CI job
export DO_NOT_TRACK=1                    # the cross-tool convention
```

```bash pnpm
pnpm exec e2e telemetry disable   # saved in ~/.config/e2e/telemetry.json
export E2E_TELEMETRY_DISABLED=1          # for a shell or a CI job
export DO_NOT_TRACK=1                    # the cross-tool convention
```

```bash bun
bunx e2e telemetry disable   # saved in ~/.config/e2e/telemetry.json
export E2E_TELEMETRY_DISABLED=1          # for a shell or a CI job
export DO_NOT_TRACK=1                    # the cross-tool convention
```
</CodeGroup>

As variáveis de ambiente prevalecem sobre a escolha salva.
`e2e telemetry enable` desfaz um `disable` salvo. `e2e telemetry` imprime o
status e, quando a telemetria está desligada, o motivo. O arquivo de
preferências fica em `$XDG_CONFIG_HOME/e2e/` quando essa variável está
definida, e em `%APPDATA%\e2e\` no Windows.

Um `disable` também vale para os comandos que já estão rodando em outro
terminal. Nada é enviado quando não é possível escrever no diretório de
preferências, nem a partir de um checkout do código-fonte do repositório do
e2e.

## Veja o que seria enviado

<CodeGroup>
```bash npm
E2E_TELEMETRY_DEBUG=1 npx e2e run
```

```bash pnpm
E2E_TELEMETRY_DEBUG=1 pnpm exec e2e run
```

```bash bun
E2E_TELEMETRY_DEBUG=1 bunx e2e run
```
</CodeGroup>

A CLI imprime os payloads exatos no stderr como `[telemetry] {...}` e não
envia nada.

## O que é enviado

Cada comando envia um evento `e2e_cli_session`. `run` e `explore` também
enviam `e2e_run_completed`, `init` envia `e2e_init_completed` (assim como
`explore`, quando roda antes o assistente do init), `upgrade` envia
`e2e_upgrade_completed`, e `mcp` envia um `e2e_mcp_session` por sessão
MCP. `--help` e `--version` não enviam nada, em nenhum comando. `run()` e
`explore()` de `e2e/runner` não enviam evento de sessão, só um
`e2e_run_completed` por chamada que retorna um relatório.

Os eventos vão em uma única requisição quando o comando, `run()` ou
`explore()` termina, com um prazo de dois segundos. `e2e mcp` envia cada
evento de sessão em uma requisição própria, e `e2e run --watch` envia o
evento de cada execução quando ela termina.

Os eventos contêm só as propriedades abaixo. Um código de erro que não é um
token em maiúsculas é enviado como `OTHER`. Um nome de engine, plataforma,
modelo, frota ou cliente MCP, ou uma versão de cliente MCP, que não é um
token simples de letras, dígitos, pontos, hífens e sublinhados é enviado
como `other`. Uma versão de engine que não segue semver é enviada como
`unversioned`. Nas contagens de ações e de chamadas de ferramenta, as
ferramentas do próprio projeto contam juntas como `tool`, e qualquer outro
nome como `other`.

## O que nunca é enviado

A telemetria nunca envia títulos de testes, caminhos de arquivos, URLs,
origens, instruções, observações, conteúdo de páginas, capturas de tela,
mensagens de erro, stack traces, valores de variáveis de ambiente,
credenciais ou conteúdo de arquivos. Ela nunca envia os nomes de alvos,
agentes, credenciais, segredos ou ferramentas do projeto, argumentos ou
resultados de ferramentas MCP, o objetivo ou os charters de uma exploração,
nem as palavras dos achados dela.

## Na CI

Execuções na CI contam como o fornecedor de CI, não como uma máquina, sem
arquivo de preferências e sem aviso. Um agente de código que define `CI` no
próprio shell, sem um fornecedor de CI em volta, conta como a máquina em que
roda.

Na CI, só as variáveis de ambiente desligam a telemetria. Defina
`E2E_TELEMETRY_DISABLED: '1'` no `env` do job.

## Em uma frota

Uma plataforma que roda o e2e para os usuários dela em máquinas novas
contaria cada máquina como um usuário novo. Defina
`E2E_TELEMETRY_FLEET=<name>` nessas máquinas. Os eventos delas contam como
`fleet:<name>`, sem arquivo de preferências e sem aviso, como na CI. Ou
defina `E2E_TELEMETRY_DISABLED=1` para não enviar nada.

## Para onde vai

Os eventos vão para `eu.i.posthog.com`, um projeto do PostHog que os
mantenedores do e2e operam. O PostHog não mantém perfil de pessoa, não
armazena o endereço da requisição e desativa o GeoIP. Os dados são lidos de
forma agregada.

A telemetria está coberta pela
[política de segurança](https://github.com/e2e-inc/e2e/blob/main/SECURITY.md).
[Conexões de saída](/reference/security#outbound-connections) lista todas as
outras conexões que uma execução pode fazer.

## Feedback

[`e2e feedback`](/reference/cli#e2e-feedback) não é telemetria. Ele envia
as palavras das flags dele como um evento `e2e_feedback` para o mesmo
projeto do PostHog, com os dados da máquina acima. Quando a telemetria está
ligada, ele tem o mesmo id anônimo dos seus eventos de telemetria.

Um `e2e telemetry disable` salvo não o impede. `E2E_TELEMETRY_DISABLED=1`
e `DO_NOT_TRACK=1` impedem. A [referência da CLI](/reference/cli#e2e-feedback)
cobre a ocultação, `--dry-run` e bugs sem `--repro`.

## O aviso

O primeiro comando, ou a primeira chamada de `run()` ou `explore()` de
`e2e/runner`, imprime no stderr um aviso que diz como desativar a
telemetria. Ele mantém intacta a saída de `--reporter json`. `e2e init` e
`e2e telemetry` não o imprimem, então ele espera pelo próximo comando. O
aviso aparece de novo depois de uma grande mudança nos dados coletados.
