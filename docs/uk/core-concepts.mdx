Тест поєднує три види кроків:

| Крок | API | Викликає модель? |
| --- | --- | --- |
| [Ціль](#goals) | `agent.act` | Так, якщо крок не [закешовано](/cache) |
| [Перевірка](#assertions) | `agent.assert`, `agent.waitFor`, `agent.extract` | Так |
| [Локатор](#locators) | `screen` і `expect` | Ні |

Із [власним виконавцем (executor)](/executors) кроки `act` і `assert` також не
потребують LLM.

```ts title="tests/todos.e2e.ts"
import { describe, test, expect } from 'e2e';

describe('todos', () => {
  test('the Done filter shows only completed todos', async ({ app, agent, screen }) => {
    await app.open('/todos');
    await agent.act('add todos "Buy milk" and "Walk the dog"');
    await agent.act('complete "Buy milk"');
    await agent.waitFor('"Buy milk" is completed and "Walk the dog" is open');

    await screen.getByRole('tab', 'Done').tap();

    await expect(screen.getByTestId('todo')).toHaveCount(1);
    await agent.assert('the only todo listed is "Buy milk"');
  });
});
```

Кожен тест перевіряє одну поведінку з однією ціллю в три етапи: підготовка
початкового стану, виконання та перевірка результату.

Виносьте повторювані локатори й значення в `const`, спільну підготовку в хук
або фікстуру, а коли кілька тестів працюють з одним екраном, створюйте
невеликий хелпер або [page object](/page-object-model), залишаючи перевірки
результату на виду в самому тесті. Короткі одноразові інструкції тримайте прямо
в рядку (довгі можна винести в локальний `const`), а повторювані інструкції
виносьте в модуль TypeScript із `params` для тестових даних.

Завжди ставте `await` перед кожним викликом `agent`, `screen` і `expect.poll`.
Якщо тест завершиться, поки крок ще виконується, e2e завалить його.

## Цілі

Метод `agent.act` отримує інструкцію природною мовою, виконує потрібні дії для
досягнення цілі та викидає помилку, якщо це не вдалося. Використовуйте назви
полів і кнопок з екрана та вказуйте порядок дій, коли він має значення
(наприклад, заповнити адресу доставки, обрати спосіб доставки й оформити
замовлення).

Починайте з одного виклику для поведінки, яку перевіряєте. Розбивайте його на
важливому переході, коли наступному кроку потрібен відомий стан (скажімо,
сторінка оплати в довгому оформленні замовлення), коли довгий сценарій ризикує
вичерпати ліміти `maxSteps` або `maxModelCalls`, чи коли проміжний збій має
відображатися окремим кроком. Поясніть у коментарі, навіщо потрібен поділ, і
дочекайтеся проміжного стану екрана перед продовженням. Кожен виклик має власні
[ліміти](/reference/agent#budgets) й може відтворюватися з окремого запису.

```ts title="Complete one checkout across two screens"
test('places an order with a saved card', async ({ app, agent, screen }) => {
  await app.open('/checkout');

  // The saved card can load after the Payment heading appears.
  await agent.act('Fill the Shipping address with {address}, then choose Continue to payment.', {
    params: { address: '12 Market Street' },
  });
  await screen.getByRole('radio', 'Test card').waitFor();
  await agent.act('Select the saved Test card and choose Place order.');

  await expect(screen.getByText('Order confirmed')).toBeVisible();
});
```

- **Чекайте після підготовки, перевіряйте в кінці.** Якщо підготовка використовує
  `agent.act`, завершіть її очікуванням початкового стану, а підсумковий
  результат перевірте у фінальному блоці. Будь-яке подальше успішне очікування
  або перевірка підтверджує попередні цілі для
  [кешу відтворення](/cache#when-a-recording-is-written).
- **Повторюйте формулювання з UI.** Використовуйте ті самі підписи й терміни,
  які справді показані на екрані.
- **Передавайте дані через `params`.** Для паролів або токенів передавайте
  об'єкт `Secret`, щоб модель ніколи не бачила відкритий текст. Див.
  [Автентифікація](/authentication).
- **Обгортайте динамічні значення в `unique()`.** Позначки часу або нові
  email-адреси змінюються щоразу, а таке обгортання дає
  [кешу змогу відтворювати крок](/cache#what-must-match):

```ts
import { unique } from 'e2e';

const email = `ada+${Date.now()}@example.test`;
await agent.act('sign up with email {email}', { params: { email: unique(email) } });
```

Коли текстового дерева замало, `agent.act` автоматично робить знімки екрана, а
на рушіях із підтримкою цієї функції може тапати й вводити текст за
координатами. Якщо ціль не вдалася, уточніть інструкцію або винесіть спільну
предметну термінологію в [`context`](/agents) агента.

## Перевірки

Агентні перевірки оцінюють поточний стан екрана незалежно. Модель бачить ваше
твердження, замаскований снепшот екрана, поточний URL або розташування та
`context` агента, без попередніх кроків і підсумків `agent.act`.

- **`agent.assert`** перевіряє екран у поточний момент і завершується помилкою,
  якщо твердження хибне або доказів недостатньо.
- **`agent.waitFor`** чекає, доки умова стане істинною, викликаючи модель лише
  після зміни екрана або розташування.
- **`agent.extract`** зчитує структуровані дані з екрана в будь-який тип
  [Standard Schema](https://standardschema.dev), наприклад Zod.

```ts
import { expect } from 'e2e';
import { z } from 'zod';

await agent.assert('the dashboard shows a trial badge');
await agent.waitFor('a download link appears', { timeout: 120_000 });
await agent.assert('the chart trends upward', { vision: true });

const data = await agent.extract('every todo title', {
  schema: z.object({ titles: z.array(z.string()) }),
});
expect(data.titles).toContain('Buy milk');
```

Перевіряючи текст, згенерований моделлю, оцінюйте зміст, а не дослівне
формулювання. Коли важливий точний текст, використовуйте [локатор](#locators).

Для візуальних перевірок, таких як графіки чи вирівнювання верстки, передайте
`vision: true` (або `vision: 'only'`, щоб оцінювати лише знімок екрана).
Зважайте, що зображення додають вхідні токени. Див.
[параметри vision](/reference/agent#vision).

## Локатори

Локатори звертаються до відомих елементів керування напряму, без виклику
моделі. Використовуйте їх щоразу, коли точно знаєте потрібну дію або очікуване
значення.

```ts
// Role and name first, label second, test ID last.
await screen.getByRole('button', 'Sign in').tap();
await screen.getByLabel('Email').fill('ada@example.test');

// Scope into a row.
const row = screen.getByRole('listitem').filter({ hasText: 'Design review' });
await row.getByRole('button', 'Archive').tap();

// Gestures and coordinates.
await screen.swipe({ direction: 'up' });
await screen.getByRole('image', 'Seat map').tap({ position: { x: 120, y: 48 } });

// Assertions retry until they pass or time out.
await expect(screen.getByRole('status')).toHaveText('2 remaining');
```

- Дії та перевірки для одного елемента падають, якщо локатор знаходить більше
  ніж один збіг. Звузьте вибір через `.filter()`, `.first()` або `.nth()`.
- Прямі зчитування на кшталт `textContent()` чекають на появу елемента, після
  чого зчитують його один раз без повторних спроб.

Див. [довідку з screen](/reference/screen) і
[довідку з expect](/reference/expect#locator-matchers). Про перехоплення
запитів, cookie, діалогові вікна та завантаження файлів читайте на сторінці
[Робота з браузером](/browser).

## Організація тестів

```ts
import { beforeEach, describe, test } from 'e2e';

describe('billing', { tags: ['billing'] }, () => {
  beforeEach(async ({ app }) => { await app.open('/billing'); });

  test('upgrades', { retries: 2, timeout: 60_000 }, async ({ agent }) => {
    await agent.act('upgrade to Pro');
  });
});

test('needs two organizations', async ({ app }) => {
  test.skip((await countOrganizations()) < 2, 'nothing to switch to');
  await app.open('/organizations');
});
```

- **Починайте якомога ближче до потрібного екрана.** Кожен тест запускається в
  окремій спробі, тож прибирайте зайву навігацію: створюйте дані у фікстурах,
  відновлюйте [збережену сесію](/authentication), відкривайте прямий URL або
  мобільний [deep link](/mobile#the-device-fixture). (Браузери створюють чистий
  контекст на кожну спробу, а мобільні пристрої зберігають стан застосунку до
  виклику `app.open()` або `app.clearState()`.)
- **Пропускайте тести за умовою** через `test.skip(condition, reason)`.
- **Об'єднуйте залежні тести** за допомогою `{ serial: true }` на блоці
  `describe`, щоб вони виконувалися по черзі на одному воркері й повторювалися
  разом.
- **Виносьте спільну підготовку й очищення** в `test.extend`. Див.
  [Написання фікстур](/fixtures).
- **Отримуйте типізовані фікстури платформ**, імпортуючи `test` із
  `@e2e-dev/web`, `@e2e-dev/mobile`, `@e2e-dev/desktop` або `@e2e-dev/electron`
  для `browser`, `device`, `desktop` чи `electron`.

Усі параметри описано в [довідці з test](/reference/test).

## Запуск одного тесту

<CodeGroup>
```bash npm
npx e2e run tests/signup.e2e.ts:12   # the test at line 12
npx e2e run --grep checkout          # tests with a matching title
npx e2e run --target web             # one target
```

```bash pnpm
pnpm exec e2e run tests/signup.e2e.ts:12   # the test at line 12
pnpm exec e2e run --grep checkout          # tests with a matching title
pnpm exec e2e run --target web             # one target
```

```bash bun
bunx e2e run tests/signup.e2e.ts:12   # the test at line 12
bunx e2e run --grep checkout          # tests with a matching title
bunx e2e run --target web             # one target
```
</CodeGroup>
