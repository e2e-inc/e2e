Кодинг-агент, наприклад Claude Code, Codex або Cursor, може писати, запускати й
налагоджувати тести e2e. Він вивчає e2e зі скілу, працює із застосунком через
`e2e mcp` сервер і читає трейси тестів, які впали.

## Встановлення скілу

<CodeGroup>
```bash npm
npx e2e init
```

```bash pnpm
pnpm dlx e2e init
```

```bash bun
bunx e2e init
```
</CodeGroup>

| Шлях | Хто використовує |
| --- | --- |
| `.agents/skills/e2e/` | Codex, Cursor, OpenCode та інші агенти, що читають `.agents/skills` |
| `.claude/skills/e2e/` | Claude Code. Посилання на `.agents/skills/e2e/`, якщо встановлено обидва варіанти. |

Команда `init` записує туди `SKILL.md` і тематичні довідки, а
[`e2e upgrade`](/reference/cli#e2e-upgrade) підтримує їх в актуальному стані.
`init` також додає вказівку в `AGENTS.md` (і в `CLAUDE.md` зі шляхом
`.claude/skills`), створюючи файл за потреби, щоб промпт на кшталт «додай тест
для оформлення замовлення» одразу підхоплював скіл:

```md title="AGENTS.md"
End-to-end tests use e2e; read .agents/skills/e2e/SKILL.md before writing or running one.
```

Без `init` встановіть скіл командою `npx skills add e2e-inc/e2e` і додайте цей
рядок вручну або виведіть скіл командою `npx e2e guide [topic]`. Пакет також
постачає цю документацію офлайн у `node_modules/e2e/docs/`.

У Claude Code, Codex і Cursor усі три e2e скіли можна також встановити як
[плагін](/reference/cli#plugins-and-skill-registries), а pnpm уміє
[створювати посилання на скіл](/reference/cli#skills-linked-by-pnpm) замість
зберігання копії.

## Доступ агента до застосунку

Команда `e2e mcp` запускає MCP сервер, який надає агенту живу сесію у вашому
застосунку у вебі, на iOS або Android. Агент бачить екран, виконує на ньому дії
та перевіряє результат своєї роботи.

| Завдання | Без `e2e mcp` | Із `e2e mcp` |
| --- | --- | --- |
| Написати тест | Вгадує локатори, запускає, отримує збій і вгадує знову | Проходить сценарій і збирає тест із рядків, перевірених у сесії |
| Змінити UI | Завершує роботу, щойно код скомпілюється | Відкриває сторінку й перевіряє результат |
| Відтворити баг | Робить припущення за кодом | Проходить кроки в застосунку |
| Виправити невдалий тест | Знову проклікує весь сценарій вручну | Запускає тест і зупиняється на кроці збою |
| Показати зміни в PR | Описує їх текстом | Записує відео |

Самому серверу модель не потрібна. Вона знадобиться лише тоді, коли тест
містить незакешований виклик агента.

### Реєстрація сервера

Команда `e2e init` пропонує зареєструвати сервер у Claude Code, Cursor і Codex,
а плагіни для Codex і Cursor уже містять його. Щоб додати сервер вручну,
встановіть залежності та запустіть клієнт у директорії проєкту:

<Tabs>
  <Tab title="Claude Code">
    ```json title=".mcp.json"
    {
      "mcpServers": {
        "e2e": { "command": "npx", "args": ["e2e", "mcp"] }
      }
    }
    ```
  </Tab>
  <Tab title="Codex">
    ```toml title=".codex/config.toml"
    [mcp_servers.e2e]
    command = "npx"
    args = ["e2e", "mcp"]
    ```
  </Tab>
  <Tab title="Cursor">
    ```json title=".cursor/mcp.json"
    {
      "mcpServers": {
        "e2e": { "command": "npx", "args": ["e2e", "mcp"] }
      }
    }
    ```
  </Tab>
  <Tab title="OpenCode">
    ```json title="opencode.json"
    {
      "$schema": "https://opencode.ai/config.json",
      "mcp": {
        "e2e": { "type": "local", "command": ["npx", "e2e", "mcp"] }
      }
    }
    ```
  </Tab>
</Tabs>

Позначте проєкт як довірений у Codex і почніть нову сесію в будь-якому клієнті.
Якщо в таргеті задано `app.command`, сесія запускає ваш застосунок і виводить
його URL та порт. Конфіг читає змінні середовища MCP сервера, а не оболонки
вашого агента.

Про `claude mcp add`, інші пакетні менеджери й помилку `Connection closed`
читайте в розділі [Налаштування](/reference/mcp#setup). Без `e2e.config.ts`
агент відкриває сесію, [вказавши рушій напряму](/reference/mcp#without-a-config).

## Приклади запитів до агента

- «Додай чекбокс Remember me у форму входу. Перевір його в застосунку за
  допомогою e2e.»
- «Напиши тест для оформлення замовлення, проходячи цей сценарій у застосунку.»
- «Відтвори issue #123 у застосунку й запиши відео.»

Додайте «headed», щоб спостерігати за локальним браузером або симулятором.

## Як агент пише й запускає тест

Скіл каже агенту спершу прочитати конфіг і наявний тест. Після цього агент
проходить сценарій у сесії `e2e mcp`. Кожна дія повертає
[рядок тесту](/reference/mcp#test_lines), який її відтворює, а будь-який інший
рядок, скажімо перевірку, агент перевіряє через
[`run_code`](/reference/mcp#run_code), перш ніж записати в тест:

```text wrap
Tapped #n31.
Test line: await screen.getByRole("button", "Sign in").tap();
```

Кожен тест перевіряє одну поведінку: підготовка початкового стану, виконання
однієї цілі та перевірка результату наприкінці.

```ts title="tests/shop.e2e.ts"
import { test, expect } from 'e2e';

test('filters the shop to items under $20', { session: 'customer' }, async ({ app, agent, screen }) => {
  const results = screen.getByRole('status', 'Results');
  const products = screen.getByRole('list', 'Products').getByRole('listitem');
  await app.open('/shop');
  await results.waitFor();
  await products.filter({ hasText: 'Leather Backpack, $90' }).waitFor();

  await agent.act('show only items under $20');

  await expect(results).toHaveText('2 items under $20');
  await expect(products).toHaveText(['Canvas Tote, $14', 'Steel Bottle, $18']);
});
```

- **Одна поведінка й одна [ціль](/core-concepts#goals) на тест.** Агент
  [розбиває довгий сценарій](/agent-steps#split-a-long-flow-into-goals) лише
  тоді, коли наступному кроку потрібен відомий стан. Перевірка наприкінці також
  підтверджує [запис](/cache#when-a-recording-is-written).
- **Іменовані локатори й жодних пауз.** Локатор, який використовується в тесті
  двічі, наприклад `results`, виноситься в `const`, щоб у разі перейменування елемента
  вистачило однієї правки. Локатори опитують екран самі, дії чекають на
  потрібний елемент, а `expect` повторює перевірку до завершення тайм-ауту.
- **Окрема сесія для кожного користувача й жодних секретів у тесті.**
  [Підготовчий тест](/authentication) виконує вхід через
  `credentials.user(name)` і зберігає сесію цього користувача. Сценарій на
  кшталт чату [відкриває другу сесію](/core#open-a-host-inside-a-test), яка
  отримує свої секрети через `launch({ secrets })`.

Під час допрацювання агент запускає лише той тест, який редагує, за номером
рядка, наприклад `npx e2e run tests/checkout.e2e.ts:3 --action-timeout 5000`,
щоб помилковий локатор падав за 5 секунд замість 30. Він залишає кеш
відтворення увімкненим, а коли тест проходить, прибирає `--action-timeout` і
запускає його один раз із `--no-cache`: див.
[Повторний запуск тесту під час виправлення](/cache#rerun-a-test-while-you-fix-it).

<a id="run-tests-next-to-a-session" />

Сесія може залишатися відкритою під час `e2e run`, якщо вони не
[конфліктують за порт або мобільний пристрій](/reference/mcp#running-tests-beside-a-session).
Кожен агент, включно із субагентами, відкриває
[власну сесію](/reference/mcp#several-sessions).

## Як агент аналізує збій

Під кожним невдалим тестом термінал виводить шлях до
[трейсу](/debugging#traces) (`❯ trace .e2e/results/<test>/trace.md`). Агент
читає `trace.md`, а не сирий `report.json`: у трейсі є рядок збою, елемент і
результат кожного кроку, помилки консолі, невдалі мережеві запити, останні ходи
агента й стан екрана на момент збою.

- **Екран, якого немає в трейсі.** Агент відкриває цей URL у сесії замість
  повторного проходження сценарію з початку.
- **Сам екран збою.** Виклик `open_session {test: "tests/checkout.e2e.ts:12"}`
  [запускає тест у сесії](/reference/mcp#running-a-test) і зупиняється на місці
  збою. Агент одразу виправляє потрібний рядок на цьому ж екрані.
- **Окремі виклики моделі.** Агент перезапускає тест із `--ai-trace --no-cache`
  і читає вивід через [unbox-ai](/debugging#agent-steps), ніколи не відкриваючи
  сирий `ai-trace.json`: він дублює промпти між ходами й може займати кілька
  мегабайтів.

## Генерація скілу перевірки для вашого застосунку

`e2e` скіл пояснює, як працює фреймворк, але не знає вашого застосунку. Скіл
`create-verification-skill` створює в проєкті локальний скіл
`.agents/skills/verify-<app>/` саме для вашого застосунку й один раз перевіряє
його перед завершенням. Встановіть його через плагін або командою
`npx skills add e2e-inc/e2e --skill create-verification-skill`, а потім
попросіть агента виконати `/create-verification-skill`. Після встановлення
через плагін він викликається як `/e2e:create-verification-skill` у Claude Code
та `$e2e:create-verification-skill` у Codex.

Згенерований скіл містить команди запуску й перевірки doctor із вашого конфігу,
два способи керувати застосунком (живу сесію `e2e mcp` і тест), перелік
доказів, які має зберігати перевірка, та мапу функцій з окремим планом `e2e explore` для
кожної з них, щоб [bug bash](/explore#bug-bashes) запускався за цією мапою. В
його основі лежить
[create-verification-skill](https://github.com/cursor/plugins/tree/main/pstack/skills/create-verification-skill)
з pstack від poteto, але замість самописного харнесу використовується e2e.
