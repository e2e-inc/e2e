Фреймворк e2e з відкритим кодом створений для тестування веб- і мобільних
застосунків. Пишіть явні [локатори](/core-concepts#locators) й
[перевірки](/reference/expect#locator-matchers), формулюйте
[цілі](/core-concepts#goals) природною мовою для AI-агента або поєднуйте обидва
підходи в одному тесті.

```ts title="tests/checkout.e2e.ts"
import { test, expect } from 'e2e';

test('a member upgrades to Pro', async ({ app, agent, screen }) => {
  await app.open('/settings/billing');

  await agent.act('upgrade the workspace to the Pro plan');
  await agent.assert('the invoice preview shows a prorated amount');

  await expect(screen.getByRole('status')).toContainText('Pro');
});
```

## Чому e2e

- **Менше підтримки тестів.** Описуйте ціль користувача замість крихких
  ланцюжків селекторів і очікувань. Коли UI змінюється, агент адаптується сам,
  тож тести доводиться виправляти рідше.
- **Швидкі й дешеві повторні запуски.** Коли крок `agent.act` проходить і
  наступна перевірка підтверджує результат, e2e
  [кешує записані дії](/cache). Надалі вони відтворюються без жодного виклику
  моделі, а агент долучається лише після змін у застосунку.

## Як це працює

- **Таргети.** Напишіть тест один раз і запускайте його в Chromium, Firefox,
  WebKit, а також на симуляторах iOS або емуляторах Android. [Вебрушій](/web) керує
  браузерами через Playwright, [мобільний рушій](/mobile) керує пристроями
  через agent-device, а за потреби ви можете
  [підключити власний рушій](/writing-an-engine).
- **Дії агента.** `agent.act` досягає цілі, а `agent.assert`,
  `agent.waitFor` і `agent.extract` перевіряють екран. Підключайте власну
  [підписку](/subscriptions), [ключ API або локальну модель](/models).
- **Звіти й безпека.** e2e [маскує зареєстровані секрети](/security) в даних
  для моделі та записує кроки, знімки екрана й трейси у [звіт](/debugging),
  який зручно читати і вам, і вашому кодинг-агенту.

## Перевірка перед релізом у CI

Перевірки перед релізом мають давати стабільний результат на кожному коміті. У
CI можна запускати e2e без звернень до моделі:

- **Тести лише на локаторах.** Пишіть тести з локаторами й `expect()` (або
  доручіть це вашому [кодинг-агенту](/coding-agents)). Їм не потрібні ані
  модель, ані ключ API.
- **Закомічені записи.** [Закомітьте кеш відтворення](/cache#commit-the-replay-cache),
  щоб у CI записані кроки `agent.act` відтворювалися без викликів моделі.
  Передайте параметр [`--strict-cache`](/cache#fail-on-a-stale-recording), щоб
  застарілий запис одразу призводив до збою замість виклику моделі. Крок без
  запису або з неповним записом усе одно
  [виконується наживо](/cache#fail-on-a-stale-recording).
- **Детерміновані перевірки.** `expect(locator)` працює локально без моделі.
  Натомість у вбудованому агенті `agent.assert`, `agent.waitFor` і
  `agent.extract` завжди викликають модель.
