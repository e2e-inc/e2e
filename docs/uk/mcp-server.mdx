Команда `e2e mcp` надає кодинг-агенту, наприклад Claude Code, Codex або Cursor, живу
сесію у вашому застосунку у вебі, на iOS або Android. Агент бачить екран,
виконує на ньому дії та перевіряє результат своєї роботи.

## Навіщо це потрібно

| Завдання | Без `e2e mcp` | Із `e2e mcp` |
| --- | --- | --- |
| Написати тест | Вгадує локатори, запускає, отримує збій і вгадує знову | Пише тест під час проходження сценарію з перевірених рядків і коду, виконаного через `run_code` |
| Змінити UI | Завершує роботу, щойно код скомпілюється | Відкриває сторінку й перевіряє результат |
| Відтворити баг | Робить припущення за кодом | Проходить кроки безпосередньо в застосунку |
| Виправити невдалий тест | Знову проклікує весь сценарій вручну | Запускає тест і зупиняється на кроці збою |
| Показати зміни в PR | Описує їх текстом | Записує відео |

Самому MCP серверу модель не потрібна. Вона знадобиться лише тоді, коли ви
запускаєте тест із незакешованим кроком агента.

## Налаштування

[Плагін e2e](/coding-agents) для Codex і Cursor уже містить сервер у вигляді
команди `npx -y e2e@<version> mcp` і запускає реліз e2e з плагіна, навіть якщо
в проєкті встановлена інша версія. У Claude Code (або без плагіна) зареєструйте
сервер у вашому проєкті. Команда `e2e init` може записати конфіг у
`.mcp.json` (Claude Code), `.cursor/mcp.json` (Cursor) і `.codex/config.toml`
(Codex) із командою вашого пакетного менеджера: `npx e2e mcp`,
`pnpm exec e2e mcp`, `yarn exec e2e mcp` (`yarn --silent exec -- e2e mcp` для
Yarn 1) або `bunx e2e mcp`. Встановіть залежності проєкту й запустіть клієнт
MCP у директорії проєкту, щоб команда використовувала встановлену версію `e2e`.
Щоб налаштувати вручну:

<Tabs>
  <Tab title="Claude Code">
    <CodeGroup>
    ```bash npm
    claude mcp add --scope project e2e -- npx e2e mcp
    ```

    ```bash pnpm
    claude mcp add --scope project e2e -- pnpm exec e2e mcp
    ```

    ```bash bun
    claude mcp add --scope project e2e -- bunx e2e mcp
    ```
    </CodeGroup>
  </Tab>
  <Tab title="Codex">
    Запустіть `e2e init --yes --skills none --mcp .codex/config.toml` за
    допомогою встановленого CLI або додайте запис нижче. Позначте проєкт як
    довірений і почніть нову сесію Codex. Команда `codex mcp list`, запущена в
    проєкті, покаже зареєстрований сервер:

    ```toml title=".codex/config.toml"
    [mcp_servers.e2e]
    command = "npx"
    args = ["e2e", "mcp"]
    ```
  </Tab>
  <Tab title="Cursor">
    Додайте сервер у файл `.cursor/mcp.json`. Інші клієнти, які читають об'єкт
    `mcpServers`, приймають той самий блок.

    ```json title=".cursor/mcp.json"
    {
      "mcpServers": {
        "e2e": { "command": "npx", "args": ["e2e", "mcp"] }
      }
    }
    ```
  </Tab>
  <Tab title="OpenCode">
    Додайте сервер у файл `opencode.json` у проєкті. Команда `opencode mcp list`,
    запущена в проєкті, покаже його зі статусом підключення:

    ```json title="opencode.json"
    {
      "$schema": "https://opencode.ai/config.json",
      "mcp": {
        "e2e": { "type": "local", "command": ["npx", "e2e", "mcp"] }
      }
    }
    ```
  </Tab>
</Tabs>

Якщо клієнт повідомляє `Connection closed`, а команда в терміналі падає з
помилкою `EBADDEVENGINES`, поле `devEngines` проєкту фіксує інший пакетний
менеджер: зареєструйте команду саме того менеджера, наприклад
`pnpm exec e2e mcp`.

Якщо в таргеті задано `app.command`, сесія запускає ваш застосунок і виводить
його URL та порт. Перша сесія для конфіг-файлу запускає його
[сервіси](/services), а остання під час закриття їх зупиняє. Конфіг читає
змінні середовища MCP сервера, а не оболонки вашого агента.

## Спробуйте без конфігу

Якщо в директорії ще немає `e2e.config.ts`, агент усе одно може відкрити сесію,
вказавши рушій напряму:

```txt
open_session {engine: "@e2e-dev/web", app: {url: "http://localhost:3000"}}
```

Для `e2e run` файл конфігу все одно потрібен. Про параметри рушія, провайдерів
пристроїв і встановлення рушіїв читайте в розділі
[Без конфігу](/reference/mcp#without-a-config).

## Приклади запитів до агента

- «Додай чекбокс Remember me у форму входу. Перевір його в застосунку за
  допомогою e2e.»
- «Напиши тест для оформлення замовлення, проходячи цей сценарій у застосунку.»
- «Відтвори issue #123 у застосунку й запиши відео.»

Додайте «headed», щоб спостерігати за локальним браузером або симулятором.

## Як сервер формує рядок тесту

Кожна дія в сесії повертає рядок тесту, який її відтворює. Локатор у цьому
рядку знайшов рівно цей елемент керування на живому екрані:

```text wrap
Tapped #n31.
Test line: await screen.getByRole("button", "Sign in").tap();
```

Агент копіює потрібні рядки в тест під час проходження сценарію. Інструмент
`test_lines` повертає всі зібрані рядки по порядку з підказками залежно від
того, чи це новий запис, відновлений тест чи підключення до призупиненого
тесту. Як формується рядок, описано в розділі
[`test_lines`](/reference/mcp#test_lines).

## Як сервер перевіряє локатор

Для рядка, який не згенерувала жодна дія (наприклад, для перевірки), агент
спершу випробовує локатор у живій сесії. Помилкове припущення виявляється одразу
там, а не під час запуску тесту:

```text wrap
0 nodes match getByLabel("Email").
A test using this locator would fail with LOCATOR_NOT_FOUND. ...

1 node matches getByRole("button", name: "Sign in").
Use: screen.getByRole("button", "Sign in")
```

## Як сервер виконує код

За допомогою `run_code` агент виконує JavaScript прямо у відкритій сесії: цикл
по списку, зчитування й обчислення значення або перевірку, яку не вивела жодна
окрема дія. Один виклик замінює багато поодиноких кроків:

```js
const rows = screen.getByRole('listitem');
const names = await rows.allTextContents();
await rows.nth(names.findIndex((name) => name.includes('Mug'))).getByRole('button', 'Add').tap();
await expect(screen.getByRole('status')).toHaveText('1 item in cart');
return names.length;
```

Рядки, що пройшли успішно, додаються до чернетки `test_lines`. Помилковий рядок
падає за лічені секунди без окремого запуску тесту:

```text wrap
Failed: LOCATOR_NOT_FOUND: locator matched no nodes within getByRole("button", name: "Save")
Test lines: 2, 1 failed.
1. await screen.getByLabel('Full name').fill('Grace Hopper');
2. failed: await screen.getByRole('button', 'Save').tap();
   LOCATOR_NOT_FOUND: locator matched no nodes within getByRole("button", name: "Save")
```

Це звичайний код JavaScript, який працює з тими самими об'єктами, що й тіло
тесту. Див. [`run_code`](/reference/mcp#run_code).

## Виправлення невдалого тесту

Виклик `open_session {test: "tests/checkout.e2e.ts:12"}` запускає один тест у
сесії й зупиняється на екрані, де стався збій. Агент читає помилку, оглядає
екран і редагує тест:

```text wrap
Test "a member checks out" (tests/checkout.e2e.ts:12) failed after 30.25s; 8 steps ran.
LOCATOR_NOT_FOUND: locator matched no nodes within getByLabel("Name")
At tests/checkout.e2e.ts:20:3
On screen, closest to what the locator asked for:
  #n32 textbox "Full name"
```

Кожна дія на цьому екрані виводить власний
[рядок тесту](#how-it-writes-a-test-line), а `run_code` одразу перевіряє
виправлений рядок. Агент підставляє ці рядки в тест замість того, що впав.

Щоб перезапустити відредагований тест, агент закриває поточну сесію й відкриває
нову з тим самим значенням `test`. Кроки агента відтворюються з кешу так само,
як у `e2e run`. Що саме запускається та які є обмеження, див. у розділі
[Запуск тесту](/reference/mcp#running-a-test).

## Запуск тестів поруч із сесією

Інтерактивна сесія не створює звітів про тести, і кеш відтворення використовують
лише тести, запущені через `open_session {test}`. Агент може залишати сесію
відкритою, поки запускає набори через `e2e run`, і одразу переходити на
потрібний екран після збою.

У вебі можливість запускати `e2e run` поруч із відкритою сесією залежить від
налаштувань `app`:

| Налаштування `app` таргета | Запуск `e2e run`, поки відкрита сесія |
| --- | --- |
| Без `command` | Обидва використовують сервер, який ви запустили самі. |
| `url` на порту [`0`](/web#let-the-runner-pick-the-port) | Кожен запускає власний екземпляр сервера (зважайте, що сервери на кшталт `next dev` не дозволяють два екземпляри в одній директорії). |
| `command` із [`reuseExisting: true`](/web#starting-your-app) | Тестовий запуск перевикористовує сервер сесії. Закриття сесії зупиняє цей сервер. |
| `command` на фіксованому порту без `reuseExisting` | Завершується помилкою, бо порт уже зайнятий. |

У CI e2e ігнорує `reuseExisting`, тож фіксований порт поводиться як в останньому
рядку. Закрийте сесію перед запуском тестів, якщо вони конфліктуватимуть за порт
або мобільний пристрій.

## Запуск кількох агентів

Кожен агент, включно із субагентами, відкриває власну сесію з власним браузером
або пристроєм, до чотирьох одночасно за замовчуванням. На мобільних платформах
виділіть для кожної сесії окремий таргет.

## Секрети

Інструмент `type_secret` або виклик `fill` у `run_code` вводять секрет, не
показуючи його агенту. Знімки екрана маскують лише захищені поля, тож секрет,
який застосунок виводить деінде, потрапить на знімок.

<Warning>
Відео, записані через `start_recording`, не маскуються.
</Warning>
