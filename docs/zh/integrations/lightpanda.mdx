[Lightpanda](https://lightpanda.io) 是从零编写的开源无头浏览器，不依赖 Chromium。它在几毫秒内启动，内存占用仅为 Chrome 的一小部分，并支持 Chrome DevTools Protocol。`@e2e-dev/lightpanda` 中的 `lightpanda()` 是它的[浏览器提供方](/browser#hosted-browsers)：每个工作进程槽位都有自己的 `lightpanda serve`，在运行开始时通过空闲端口启动，运行结束时停止。

<Note>
网页端引擎无法在 Lightpanda 中打开页面。打开页面的测试会超时。参阅[不支持的功能](#what-does-not-work)。
</Note>

## 配置

安装包：

<CodeGroup>
```bash npm
npm install --save-dev @e2e-dev/lightpanda
```

```bash pnpm
pnpm add -D @e2e-dev/lightpanda
```

```bash bun
bun add -d @e2e-dev/lightpanda
```
</CodeGroup>

然后安装提供方要启动的 Lightpanda nightly 二进制文件：

<CodeGroup>
```bash macOS
brew install lightpanda-io/browser/lightpanda
```

```bash Linux
curl -L -o lightpanda https://github.com/lightpanda-io/browser/releases/download/nightly/lightpanda-x86_64-linux
install -D -m 755 lightpanda ~/.local/bin/lightpanda
```
</CodeGroup>

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { lightpanda } from '@e2e-dev/lightpanda';

export default {
  targets: [
    {
      name: 'lightpanda',
      engine: web({ browser: lightpanda() }),
      app: { url: 'http://localhost:3000' },
    },
  ],
} satisfies E2EConfig;
```

提供方会运行 `PATH`、`~/.lightpanda/lightpanda` 或 `~/.local/bin/lightpanda` 中的 `lightpanda`，这些也是 [agent-browser](https://agent-browser.dev/engines/lightpanda) 查找的位置；也可以使用启动 `e2e run` 时环境中的 `LIGHTPANDA_PATH` 或选项中的 `binary` 指定二进制文件。如果都找不到，运行会在执行任何测试之前失败，并给出安装页面。
每个工作进程都有自己的服务器，因此 `workers` 决定同时运行多少个服务器，运行日志会列出每个服务器：

```text
ℹ lightpanda (1 of 2): lightpanda 1.1.0-nightly at ws://127.0.0.1:51165/
```

## 连接正在运行的服务器

对于已经运行的 Lightpanda（例如 CI 中的 Docker 镜像），应使用 [`connect`](/reference/web#options) 测试目标，而不是提供方：引擎会连接到其 CDP 端点，结束后保留服务器运行。

```ts title="e2e.config.ts"
web({ connect: { cdpEndpoint: () => process.env.LIGHTPANDA_URL ?? 'ws://127.0.0.1:9222/' } })
```

```bash
docker run -d --name lightpanda -p 127.0.0.1:9222:9222 lightpanda/browser:nightly
```

这样所有工作进程都会共享该服务器。一个 `lightpanda serve` 默认接受 16 个连接；运行更多工作进程时，将它的 `--cdp-max-connections` 调整为大于 `workers` 的值。

## 选项

| 选项 | 默认值 | 含义 |
| --------------- | ------------------------------- | ------- |
| `binary` | `LIGHTPANDA_PATH`，否则自动查找 | 要启动的二进制文件：路径或 `PATH` 中的名称。 |
| `loadResources` | `[]` | 服务器获取的子资源：`iframe`、`image`、`stylesheet`。参阅[获取更多页面资源](#fetch-more-of-the-page)。 |
| `args` | `[]` | 额外的 `lightpanda serve` 标志，放在提供方设置的标志之后。 |

提供方在本次运行中为每个工作进程槽位租用一个服务器。如果服务器在十秒内未在其端口上响应，或二进制文件提前退出，租用会失败，并在消息中附上标准错误输出。

## 获取更多页面资源

`lightpanda serve` 默认不请求任何子资源：没有图片、外部样式表或 iframe。使用 `loadResources` 可以逐项启用，对应服务器的 `--load-resources`：

```ts
web({ browser: lightpanda({ loadResources: ['stylesheet', 'iframe'] }) })
```

## 支持的功能

只有不需要页面的功能可用。使用 2026 年 11 月的 Lightpanda nightly（`1.1.0-nightly.12226`）运行 e2e testbed 的本地测试套件时，只能做到以下几点：

- 提供方为每个工作进程槽位启动一个服务器，并在运行结束时停止它。
- 不打开页面的测试可以通过，例如使用 `fetch` 调用 API 的测试。

## 不支持的功能

无论使用提供方还是 [`connect`](#attach-to-a-running-server)，打开页面的测试都无法通过。所有查询、操作、断言和[智能体步骤](/agent-steps)都需要页面。

| 功能 | 实际行为 | 原因 |
| ------- | ------------ | --- |
| 打开页面：`app.open`、`browser.goto` | 调用始终不返回。测试会在其 [`timeout`](/reference/config#timeout) 结束时失败，错误为 `TEST_TIMEOUT` 或 `ACTION_FAILED`。 | Lightpanda 不会以引擎能读取的方式报告新页面。 |
| [会话](/authentication)（在 `test.setup` 中使用 `session.save`，在测试上设置 `session:`） | 准备测试会以同样的方式超时，e2e 会跳过每个使用其会话的测试。 | 准备测试无法打开页面。 |

修复需要 Lightpanda 自身做出改动。请改用 Chromium 测试目标运行测试套件。
