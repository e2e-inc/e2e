Every runner error carries a class and a code. The class sets the exit code,
and the code names the cause. `e2e login`,
`e2e logout`, and `e2e models` are the exception, under
[Exit codes](#exit-codes).

```ts title="tests/upgrade.e2e.ts"
import { isAgentError, test } from 'e2e';

test('upgrade to Pro', async ({ agent }) => {
  try {
    await agent.act('upgrade the workspace to Pro');
  } catch (error) {
    if (isAgentError(error) && error.code === 'STEP_TIMEOUT') {
      // the step ran out of time; the message carries the last judgment
      console.error(error.category, error.details);
    }
    throw error;
  }
});
```

## Reference

### Exit codes

| Class | Exit code |
| --- | ---: |
| test | 1 |
| configuration | 2 |
| infrastructure | 3 |
| internal | 4 |
| interrupted | 130 |

- In a mixed run the highest-precedence code present wins,
  `130 > 4 > 3 > 2 > 1 > 0`. The report keeps every individual result.
- A test whose cleanup failed (a required video that was not
  finalized, a session that did not close) exits with that cleanup error's
  code, usually 3.
- A setup assertion failure is a test failure and skips its dependents.
  Missing setup infrastructure keeps its configuration or infrastructure
  class.
- The `internal` class and exit code 4 are reserved for runner invariant
  violations. No first-party code raises a code in that class today.
- `e2e login`, `e2e logout`, and `e2e models` print a failure's message with
  no code and exit 1, or 130 when a sign-in or picker is cancelled.

Whether a CI job is worth retrying depends on the code:

| Exit | Meaning | Retry the job? |
| ---: | --- | --- |
| 1 | A test failed | Only if the test is flaky |
| 2 | Configuration, collection, or policy | Fix the reported problem first |
| 3 | Engine, app process, model provider, artifact, or cleanup infrastructure failure | If the cause is temporary |
| 4 | An internal runner error | Report it |
| 130 | The run was interrupted | |

| Codes | Description |
| --- | --- |
| [Agent codes](#agent-codes) | The `code` of an `AgentError` |
| [Runner codes](#runner-codes) | Plain strings in output and report |
| [Test code errors](#test-code-errors) | Thrown from test code |

### AgentError

`AgentError` is the runner-classified agent failure, exported from `e2e`.

```ts
export class AgentError extends Error {
  readonly code: AgentErrorCode;
  readonly category: 'test' | 'configuration' | 'infrastructure' | 'internal' | 'interrupted';
  readonly retryable: boolean;
  readonly details: ErrorDetails | undefined;
  readonly explanation: string;
  readonly screenshot?: string;
  readonly blocked: boolean;
}
```

| Field | Description |
| --- | --- |
| `code` | One of the [agent codes](#agent-codes), assigned by the runner and never taken from model text. |
| `category` | The error class under [Exit codes](#exit-codes). It sets the exit code. |
| `details` | Structured facts: locator, expected, observed, match count, wait time. |
| `explanation` | Sanitized, bounded prose. The same value as `message`. |
| `screenshot` | An artifact path, present only when evidence was captured and permitted. |
| `blocked` | `true` when the failure reports a blocked step, not a product failure. |

<Note>
In a test file, `instanceof AgentError` can be false. Use `isAgentError`
from `e2e` and branch on `code`, as in the example at the top of this page.
</Note>

| `ASSERTION_FAILED` | `agent.assert` judged false, or a locator, `browser`, or value matcher failed | test | 1 |

| `STEP_NO_CONCLUSION` | The executor used every turn without calling `complete_step`. The step fails with the agent's last summary | test | 1 |
| `REPLAY_STALE` | Under `cache.strict` or `--strict-cache`, the step's recording exists but no longer replays, so the step fails with no model call instead of handing off to the agent. `step.cache.reason` is one of `invalid-entry`, `wrong-context`, `target-not-found`, `target-ambiguous`, `viewport-changed`, `action-failed`, `action-uncertain`, `end-mismatch`, or `no-entry` while the cache directory (not a custom `cache.store`) holds a recording of the step under another key, which the message names. ## Common errors

The codes a failed run shows most often, with the usual cause and the fix.
[Debugging a run](/debugging) walks through a failure.

| Code | Usual cause | Fix |
| --- | --- | --- |
| `APP_UNREACHABLE` | Nothing answers at `app.url`, or `app.command` never became ready. On iOS, the message may name the automation runner instead | Set `app.command.log` and read it; check the port; raise `app.command.startupTimeout`. For the iOS runner, follow the message (see [Mobile](/mobile#troubleshooting)) |
| `APP_ALREADY_RUNNING` | Something already serves `app.url` when the runner wanted to start `app.command` | Stop it, or set `reuseExisting: true` for local runs |
| `LOCATOR_NOT_FOUND` | Wrong role or name, text not exact, element inside an iframe, page not open | Read the markup for the accessible name; try `exact: false`; `browser.frameLocator` for iframes; `--headed` to look |
| `LOCATOR_AMBIGUOUS` | Two matches: a hidden duplicate, a repeated label | Add `{ name }`, scope under a container, `filter`, `first()`, or `{ visible: true }` |
| `ASSERTION_FAILED` | The expectation is wrong, or the state settles after 5 s; for `agent.assert`, the judgment was false | Compare with the screenshot; `{ timeout }` on the matcher; rewrite the question |
| `ASSERTION_INCONCLUSIVE` | `agent.assert` or `agent.extract` asked about something the screen doesn't show: on another page, still loading, or only in pixels | Open or wait for the right screen first; add `vision: true` when the answer is in pixels (the message says so) |
| `ACTION_FAILED` | Element covered, disabled, or detached, or an operation timed out | Wait on the right condition with `expect` first; close overlays |
| `STEP_BUDGET_EXHAUSTED`, `STEP_TIMEOUT` | The agent ran out of actions, model calls, or time | Scope the goal to one step. Raise the agent entry's `maxSteps` or `maxModelCalls` for the budget, the config `timeout` for an `act` step, or the agent's `judgmentTimeout` for `assert`, `waitFor`, and `extract` |
| `MODEL_UNAVAILABLE` | No model constructed in the config, or GitHub Copilot doesn't serve the configured model to your account | See [Models](/models); for Copilot, [Pick a model](/subscriptions#pick-a-model) |
| `MODEL_PROVIDER_FAILED` | Missing or bad key, rate limit, no credits, or every try of one request went 120 s without an answer | Check the key the provider reads and the quota; for a slow local model, a smaller screen (`agents.<name>.maxObservationBytes`) or a faster model |
| `MODEL_REFUSED` | The model refused the prompt (finish reason `content-filter`). Exit 1 | Rephrase the instruction, or switch to another model |
