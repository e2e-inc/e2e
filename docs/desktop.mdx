---
title: Desktop
description: Test a native or Electron desktop app on macOS through its accessibility tree.
---

`@e2e-dev/desktop` runs tests on desktop apps: native apps and Electron
apps. It reads and drives the app through the OS accessibility tree with
[agent-desktop](https://github.com/vercel-labs/agent-desktop). Tests use the
same `agent`, `screen`, and `expect` APIs as browser tests.

<Note>
  The desktop engine is a prototype. It is tested on macOS. Windows and Linux
  use the same commands, but they are not tested yet.
</Note>

## Set up

Install the runner and the engine:

<CodeGroup>
```bash npm
npm install --save-dev e2e @e2e-dev/desktop
```

```bash pnpm
pnpm add --save-dev e2e @e2e-dev/desktop
```

```bash bun
bun add --dev e2e @e2e-dev/desktop
```
</CodeGroup>

On macOS, the app that starts e2e needs two permissions in **System Settings
> Privacy & Security**. That app is your terminal, your IDE, or your CI agent.

- **Accessibility**, to read and drive the app.
- **Screen Recording**, for screenshots.

The first run downloads agent-desktop and checks its SHA-256 digest. To use
your own install, such as a Homebrew one, set
`desktop({ binary: '/path/to/agent-desktop' })`.

Check your setup:

<CodeGroup>
```bash npm
npx e2e doctor
```

```bash pnpm
pnpm exec e2e doctor
```

```bash bun
bunx e2e doctor
```
</CodeGroup>

It checks agent-desktop, both permissions, and the `appPath` build.

## Point at your app

Set the target's `app.appPath` to a built `.app` bundle. Or set
`app.bundleId` to an installed app's bundle id or name, such as
`com.apple.TextEdit`. `app.launchArguments` go to every launch.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { desktop } from '@e2e-dev/desktop';

export default {
  targets: [
    {
      name: 'mac',
      engine: desktop(),
      app: { appPath: 'build/MyApp.app' },
    },
  ],
  credentials: {
    ada: { username: 'ada', password: process.env.ADA_PASSWORD ?? '' },
  },
} satisfies E2EConfig;
```

## Write a test

Import `test` from `@e2e-dev/desktop`. `app.open()` launches the app. When
the engine launched it before, it quits that copy first. A copy you opened
yourself is left alone, and the engine never reads or drives it. Every test
ends with the app quit.

```ts title="tests/sign-in.e2e.ts"
import { test } from '@e2e-dev/desktop';
import { credentials, expect } from 'e2e';

test('signs in', async ({ app, screen }) => {
  const ada = credentials.user('ada');
  await app.open();
  await screen.getByRole('textbox', 'Username').fill(ada.username);
  await screen.getByRole('textbox', 'Password').fill(ada.password);
  await screen.getByRole('combobox', 'Plan').selectOption('Team');
  await screen.getByRole('button', 'Sign in').tap();
  await expect(screen.getByTestId('status')).toContainText('Signed in as ada');
});
```

Roles use the names the web uses: `textbox`, `checkbox`, `combobox`,
`button`. Static text has the role `text`, so find it with `getByText`.
`getByTestId` finds the developer id: `AXIdentifier` on macOS, and a DOM
`id` in an Electron app.

The `desktop` fixture lists the app's windows (`desktop.windows()`) and
quits the app (`desktop.closeApp()`).

## What differs from the web

| Area | On a desktop target |
| --- | --- |
| Input | Actions use the accessibility API. Your pointer and focus stay where they are |
| Pointer | `doubleTap`, `hover`, and point taps need `desktop({ headed: true })`, which moves the real pointer |
| Select | `selectOption` takes an option's label, not an index |
| Workers | One per target, because its workers would share one screen. Two desktop targets can still run at the same time: with `headed: true`, set `workers: 1` in the config |
| State | `app.clearState()` is not supported |
| Secrets | A password field shows no value, and screenshots paint it black |

A screenshot that cannot cover a password field is not saved.

## Options

| Option | Type | Default |
| --- | --- | --- |
| `binary` | `string` | the downloaded release |
| `snapshot` | `'full' \| 'interactive'` | `'full'` |
| `headed` | `boolean` | `false` |
| `settle` | `number \| false` | `150` |

`snapshot: 'interactive'` reads only controls, without static text. `settle`
is how long the engine waits after an agent action before the agent reads
the screen, in milliseconds.
